# 裝幀工房 BINDERY — 设计思路与设计方案

> Kami 紙匣 · 合并稿 D（`preview/pitch-d-bindery.html`）
> 血统：提案 A「無限裝訂」之皮 × 提案 C「紙匣製作所」之骨；吸收 Grok 样张两版的系统层约定。
> 版本：2026-10-26 · 静态稿 v1 · 仅供评审

---

## 0. 一句话概念

**一册由流水线装订出来的、永不封卷的个人画集。**

- 产品叙事主轴（三幕）：**从「刷过」→ 到「收藏」→ 到「重逢」**。
- 品牌双关：kami = 「紙」亦读「神」；纸匣 = 盛放「流」的容器。
- 命名巧合是本次合并的合法性来源：A 讲装订的**结果**（一部画集），C 讲装订的**过程**（一条产线）——两案共用同一个核心词「装订」，因此合并不是折衷，而是补全。

## 1. 血统与决策记录

| 来源 | 贡献 | 状态 |
|---|---|---|
| 提案 A 無限裝訂 | 视觉身份：和纸白/油墨黑/朱印红、纵书、套印错位、奥付排字机、裁切线与微排版元数据 | ✅ 采纳为「皮」 |
| 提案 C 紙匣製作所 | 结构与动效：五工序叙事、传送带、爆炸分解、微型流水线、检索台、工业图标 | ✅ 采纳为「骨」 |
| 提案 B 墨之海 | 沉浸式 WebGL 墨海 | ❌ 用户裁决弃用（与纸张世界观冲突）；其「收藏即仪式」已由 A 的盖章表达 |
| Grok · kami-ia（信息架构样张） | room 词汇（vault/look/queue/seal）、paper/desk 双墨色模式 | ✅ 系统层吸收（见 §8） |
| Grok · kami-binding（装帧） | 桌上纸页 desk/sheet 隐喻、装订线 thread 红、day/night | ✅ 系统层吸收（见 §8） |

**为什么 A×C 成立**：A 解决「这是谁」（身份辨识度，与「纸质·收藏·私有」的产品气质咬合）；C 解决「它凭什么好用」（五工序与真实功能一一对应——跨站检索、可靠队列、本地馆藏是纸匣的护城河，浏览谁家都能做）。牛皮纸不是与和纸竞争的世界观，而是印刷世界里的「车间材料色」。

## 2. 设计原则

1. **Do less, but better**：一次只讲一道工序；每段一个主交互，不为动而动。
2. **交互即叙事**：检索要真的能「打」，队列要真的在「带」上走，入藏要真的「盖章」——演示即功能预告。
3. **一以贯之的朱红**：`#C93A2B` 是唯一的动作色/承诺色，只盖在「发生了收藏行为」的地方。
4. **纸面优先**：一切浮层、卡片、印章都保持「印在纸上」的物理感（multiply 混合、错位阴影、纤维噪点）。

## 5. 版式语法

- **一张纸（铺纸工作台）**：视口即一页纸——14px 内缩细线框 + 左竖分栏线 + 纤维噪点；区块一律用 1px 线分割（线分纸，不用盒子）。
- **纵书**：主标题 `writing-mode: vertical-rl`，副文纵排配 `letter-spacing .5em`。
- **不对称 12 列**：図版网格用 span 4/5/6 + 负 margin 制造错落；禁止三等分。
- **微排版元数据**：四角裁切线、实时时钟、章节编号（工程 0X/05）、坐标 N35.6812 E139.7671、SN 编号——每屏必有。
- **右缘奥付**：hover 図版 → 右缘 aside 逐字排版该图版 colophon（打字机 22ms/字）。

## 6. 动效系统

| 名称 | 规格 | 用在哪 |
|---|---|---|
| 揭示 reveal | `translateY(26px)→0`，`.9s cubic-bezier(.16,1,.3,1)`， stagger `.08s` | 全部 `.rv` |
| 套印错位 hover | 边框 `translate(-3px,-3px)` + cyan/vermilion 双向硬阴影 | 図版卡 |
| 盖章 stampIn | `scale(3.2) rotate(-16deg) blur(3px) → scale(1) rotate(-8deg)`，`.5s ease-out`，`mix-blend: multiply` | 朱印/受付/閲覧 |
| 传送带 belt | `translateX(0→-50%)`，`16s linear infinite`（双份内容无缝循环） | 队列 |
| 状态章脉冲 | opacity `.45↔1`，`1.6s` | 下載中 |
| 爆炸分解 explode | CSS 变量 `--ex: 0→1`（滚动进度驱动）→ `translateY(calc(var(--ex) * var(--off)))`，四层错位 | 归档 |
| 逐枚入藏 | `--ex` 阈值 `0.28/0.58/0.86` 各触发一枚 stampIn（顺序 if，跳滚可一次补齐） | 归档 |
| 书架点亮 | IO `threshold .4` + `140ms` 递进 | 重逢 |
| 打字机 | 46ms/字，删除 14ms/字，停 1.7s | 检索台 |
| 机械臂 | 关节 `rotate ±9°`，`6s ease-in-out`，卡片下落同步 | hero |

**工程约束**：所有滚动驱动逻辑走 `scroll` 监听 + rAF 节流（passive）；尊重 `prefers-reduced-motion`（全部动画停用、状态直出）；本静态稿零外部 JS 依赖，双击即开。

## 8. 与 Grok 样张的统一路线（系统层吸收）

Grok 两版（kami-ia / kami-binding）与 A/C/D 共享同一纸墨印基因（其纸 `#f3efe8/#f4efe6` ≈ D 的 `#F4EFE4`；墨 `#141210/#1c1814` 同族），但定位不同：**D 是叙事/品牌层，Grok 版是产品 UI 层**。两层并入同一设计系统：

1. **双墨色模式**：采纳 `data-ink="paper|desk"`（日间纸白/夜间桌面暗），注册为系统级 token 对；D 稿后续可加 desk 模式彩蛋。
2. **room 词汇表**：采纳 IA 样张的 `vault（库）/ look（看）/ queue（队列）/ seal（印）` 作为产品信息架构命名，与 D 的五工序映射：look→01/02、queue→03、vault→04、seal→入藏仪式、（05 重逢=look 的回访态）。
3. **桌上纸页隐喻**：kami-binding 的 desk/sheet（暗色桌面上摊纸页 + 朱线装订）非常适合**灯箱/大图查看器**——「把图放到桌上看」，与 D 世界观零冲突，建议作为查看器规范。
4. **印红双档**：见 §3 争议位——`seal--bright #C93A2B`（叙事面）/ `seal--deep #8F3D32`（产品面）。

## 9. React 移植建议（下一步）

- **组件切分**：`<BinderyHero/>` `<ProcessIndex/>` `<PlateGrid/>`（含 ColophonAside 上下文）`<SearchConsole/>` `<QueueBelt/>` `<ArchiveExplode/>`（滚动进度由 `useScrollProgress(sectionRef)` hook 提供）`<StampCard/>` `<PlateShelf/>` `<WorkOrder/>`；tokens 进 `styles/tokens.css`（CSS vars 原样迁移）。
- **动效升级位**：静态稿的手写 rAF 滚动进度 → GSAP ScrollTrigger（scrub）；揭示 → GSAP batch 或 Lenis + IO 保持亦可；stampIn 保留 CSS keyframes（足够好）。
- **素材**：生成式 SVG 図版保留为 `<PlateArt variant="moon|halftone|brush|press|novel|index"/>`，正式版可换真实缩略图 + SVG 占位骨架。
- **注意**：仓库为 Next.js（Trellis 管理），移植时按 `.trellis/spec/frontend` 规范落地，走任务流程。

## 11. 首屏 v2（2026-10-26 追加）：铺纸 × 案头级自定义

用户裁决：首屏采用 kami-ia 样张的「铺纸」语法，且**必须像产品「案头」一样可自定义**（everything can redesign）。

### 11.1 铺纸解剖（为何好看）
一张纸（细线框分纸而非盒叠纸）；tile 以 `clip-path: inset(100% 0 0 0)→inset(0)` 从下往上逐格铺开（0.95s stagger）；左栏 88px 纵排导航、当前项衬线斜体；mono 计数标签（信夹 03 / 纸叠 2）。

### 11.2 首屏构成
- **左栏 rail**：纵书「流ヲ、冎ヘ。」+ 五工序纵排导航（scroll-spy，当前项朱红衬线斜体）
- **主区**：sheet-label「今日的纸 · 铺纸」+ 四格図版条带 + 右上印章头「今日の紙/廿六」（numberToCn）
- **右栏纸条**：信夹 / 纸叠 / 画师墙（产品词汇直译）+ 托盘（编辑时出现）
