## 4.1 环境要求

- Node ≥22（engines 下限；**推荐 24 = 当前 Active LTS**，CI/Docker/开发机均已 24）；pnpm 10.15.1（corepack）。
- 可选：系统 curl（出站降级通道）、Chromium/Chrome（登录中转；puppeteer-core 不自带浏览器，Docker 镜像内置）、Postgres（设 `DATABASE_URL` 即启用，否则 PGlite 内存库+快照）。

## 4.2 常用命令

```bash
pnpm dev            # 开发（0.0.0.0:8080，经 with-app-env.mjs 注入 kami-config 环境）
pnpm build          # next build（standalone）+ scripts/migrate.mjs（无 DATABASE_URL 自动跳过）
pnpm start          # 生产启动（0.0.0.0:8080）
pnpm typecheck      # tsgo --noEmit（TS 7 原生预览编译器）
pnpm test           # 三连：scripts/*.test.mjs → src/lib/**/*.test.ts（strip-types）→ src/**/*.test.tsx（tsx loader）
pnpm test:components# 仅组件测试（RTL，jsdom）
pnpm test:coverage  # c8 --all（src 全量计入，未测文件如实记 0）
pnpm test:e2e       # Playwright（webServer=e2e-server.mjs，KAMI_ROOT→仓库外临时根，专用 8090 端口）
pnpm lint / format  # ESLint 9 / Prettier
node scripts/qa-*.mjs   # 手动 QA 四件套（真实浏览器+真实网络，不在 CI）
```

**验证口径**（AGENTS.project.md）：`pnpm typecheck` + `pnpm test`；改用户可见行为必写 `CHANGELOG.md` 并开 PR（用户明说「不要 pr / 直接 commit」时听用户的）。

## 4.3 部署形态

| 形态 | 步骤 | 要点 |
| --- | --- | --- |
| 本机 dev | `pnpm i && pnpm dev` | 绑 0.0.0.0:8080（kami.config.json）；Next16 dev 需 `allowedDevOrigins`（已配 127.0.0.1/localhost/[::1]/LAN IP——**LAN IP 是本机特定值，DHCP 变了要跟补** next.config.ts）；不加白名单的症状：HMR WebSocket 拒连、客户端水合整体挂掉（页面只剩骨架卡、零数据请求） |
| 本机生产 | `pnpm build && pnpm start` | build 阶段**不触碰数据库**（db.ts 显式跳过 production-build phase——2026-09-11 构建触发快照回写丢凭据事故后的加固）；build 尾自动迁移（无 DATABASE_URL 跳过） |
| Docker | `docker compose up --build` | 两阶段 node:24-bookworm-slim；runner 装 curl+chromium+noto-cjk；standalone 产物 + migrations；命名卷 `kami-data:/app/.data`；HEALTHCHECK curl `/`（30s/5s/20s/3 重试）；`VITE_AUTH_ENABLED` 默认 "true"，ARG 可覆盖；文件首两行 `# syntax=` + `# check=skip=SecretsUsedInArgOrEnv` 是 parser 指令（必须在所有注释之前，勿下移）；**镜像随 main 自动发布 GHCR（#148）**：`docker compose pull && docker compose up -d` 一键升级，`--build` 本地构建不变（GHCR 包首发默认 private，改 public 或 `docker login ghcr.io` 一次） |
| LAN 令牌形态 | `--build-arg VITE_AUTH_ENABLED=false` | 数据面改走 24B 配对令牌（.data/lan-token.json；终端打印 `http://<ip>:8080/#pair=<token>`；三通道 header/?token=/cookie；泄露=删文件重启换新） |
| ~~Vercel~~ | 已实质废弃 | serverless 只读文件系统与 .data 假设冲突；`.vercel/` 残留已清（#148，实为旧 nitro 构建产物） |

## 4.4 环境变量与配置

| 变量 | 作用 | 缺省行为 |
| --- | --- | --- |
| HOST / PORT / KAMI_PROXY | 监听与出站代理 | kami.config.json 兜底（0.0.0.0:8080） |
| DATABASE_URL | Postgres/Neon 连接 | 未设 → PGlite 内存库 + 快照 |
| VITE_AUTH_ENABLED | 应用账号开关（构建期注入） | 默认 true |
| BETTER_AUTH_SECRET | auth 签名密钥 | 未设 → 生成并落 `.data/auth-secret.json`（跨重启保持登录） |
| KAMI_ROOT | .data/migrations 定位根 | cwd 向上 walkUp 识别（兜底 cwd——从任意目录启动会落错位置，建议显式指定） |
| PUPPETEER_EXECUTABLE_PATH | 登录中转浏览器 | 本机找系统 Chrome |
| KAMI_CHROME / KAMI_APP_ENV | 逆向/e2e 辅助 | — |

`kami.config.json`（本地，不入库，example 为模板）：host/port/proxy/throttle（media 并发闸）/水位阈值；**mtime 热读**，改完即生效。代理优先级：saved（.data/proxy.json）> config > env。`.env.example` 覆盖主要变量。

## 4.5 数据库初始化与迁移

- PGlite 形态：**零初始化**——首次 `getSql()` 自动按 basename 字母序应用 `migrations/0001~0004`；数据持久化靠 JSON 快照。
- Postgres/Neon 形态：`pnpm build` 尾自动 `scripts/migrate.mjs`（也可 `pnpm db:migrate` 手动）；**迁移无 down 脚本**——回滚 = 回代码 + 手工处理 schema 差异（历史上未出现不兼容 down 需求）。
- 新迁移规则：文件名字母序必须在既有之后；auth 类模板放 `migrations/auth/`（不递归执行）；~~jsonb 列名同步白名单~~ 已改 information_schema 自动枚举（#144），无需人工同步。

## 4.6 运维要点

- **数据位置**：一切在 KAMI_ROOT 下 `.data/`（布局见 03 号 3.3 D 节）。**备份** = 设置页导出 JSON（可选口令加密 v2）+ 停机后直接拷贝 `.data/`。
- **日志**：pino 结构化日志（#146）——默认一行人类可读（保留 `[模块:操作]` 标签），`KAMI_LOG_FORMAT=json` 切 JSON 行、`KAMI_LOG_LEVEL` 调级别；每条自动带请求 id，API 响应头 `X-Request-Id` 供报障对账；`.server` 层 console 口径已清零；无集中收集（长期项）。上游健康：设置→说明「上游健康」卡片，或 `GET /api/health/upstream`（会话）。
- **健康检查**：Docker 用 `/`（无专用健康端点）。
- **升级**：拉新代码 → `pnpm i` → `pnpm build`（自动增量迁移）→ 重启；Docker 形态 `docker compose pull && docker compose up -d`（镜像随 main 自动发 GHCR）。
- **回滚**：代码回滚；PGlite 形态 schema 随快照结构走，通常无需手工处理；必要时删 `.data/kami-db-snapshot.json` 回到最近一次导出。
- **故障恢复**：PGlite 损坏/丢快照 → 账号库回到最近快照（最差丢 30s）；个别行恢复失败隔离在 `.restore-failed.json` 供人工处置；vault SQLite 与文件双自洽；缓存目录可整删（自动重建）。
- **磁盘治理**：media 2GB / source 512MB 水位自动淘汰；rankings 有保留上限（TD-31 ✅）；vault 增长看 `/vault/stats` 存储卡。
- **CI 流水线**（.github/workflows/ci.yml，PR + main push，并发去重）：`verify`（typecheck→coverage 包装的 test→lint→build，覆盖率仅报告不卡门禁 #144）+ `docker`（buildx 构建不推送，源于 pnpm-lock 被 .dockerignore 排除事故）+ `e2e`（playwright chromium 打真实上游 yande，retries=1 兜抖动，关键路径软通过）。另有 `docker-release.yml`（main/tag→GHCR 镜像发布；**打 `v*` tag 即出版本镜像**，发版惯例=合并后打 annotated tag，如 v0.10.8）与 `refresh-fixtures.yml`（上游解析样本手动刷新，仅 workflow_dispatch，防 GitHub 出口 IP 常态打上游）。**构建口径**：`next build` 走 Turbopack——运行时才定界的动态 fs 路径（.data 目录、系统 Chrome 探测）必须内联 `/*turbopackIgnore: true*/` 注释（现存 8 处：media-cache.server.ts 4 + browser-login.server.ts 4，#158 后构建警告清零），漏加的 symptom 是 Turbopack 警告「静态分析无法追踪的动态读取」乃至整仓被追踪进产物。

## 4.7 故障排查速查

| 症状 | 先查 |
| --- | --- |
| 页面只剩骨架卡、零数据请求（dev） | allowedDevOrigins 白名单缺当前访问源（Next16 dev 源校验） |
| Pixiv 通、FANBOX 全 401 | 没走 `/auth/start` 回转；或请求缺 `Origin: https://www.fanbox.cc` |
| 图片裂开、媒体 403 | pximg 缺 Referer（应走 /api/media 代理） |
| 登录后没头像、后续 401 | 抓到的是访客 PHPSESSID（无下划线）；等 `数字ID_令牌` |
| 配了代理（Clash/mihomo fake-ip）后未缓存图片全裂、报 400 非法地址 | 媒体守卫解析闸——0.10.3（#153）起 fake-ip 段 198.18/15 视为代理托管解析放行、配出站代理时整道闸跳过；见此症状先确认镜像版本 ≥0.10.3 |
| 列表空 / 突然 401 | 上游改版——按 02 号 2.8 方法论重走逆向循环；mapping.test.ts 固定样本会红 |
| 重启后应用账号掉线 | BETTER_AUTH_SECRET 未持久（现应落 .data/auth-secret.json；旧版本升级后需重登一次） |
| `.data` 落错位置 | KAMI_ROOT 兜底 cwd；从非项目目录启动必须显式指定 |
| e2e 写进真实数据 | 不应发生（专用 8090 + 仓库外临时根）；若复用了手工起的 dev server 请停掉再跑 |

## 4.8 工程约定（权威源：AGENTS.project.md + comments.md）

- **注释三段式**（comments.md）：文件头回答**作用/用法/为什么**；只给「非显而易见的取舍」写函数注释；改行为时把「为什么」一起改。「为什么」注释是本仓库最重要的知识资产（例：curl-fetch.server.ts:4-9 连接池动机、media.ts:3-6 SSRF 自认）。
- `.server.ts` 后缀 = 服务端专属；防客户端误引靠命名约定 + db.ts 运行时抛错 + **eslint 双边界**（M10：客户端文件禁 import `*.server`；storage/sync 禁反向依赖 routes/components）。
- **数据通道铁律**：「下载」「收入纸匣」必走 `enqueueWork`，禁止另存旁路；Cookie 只走 browser-login 通道；真实 PHPSESSID 禁止进仓库/测试/截图/changelog。
- **审美铁律**：墨黑书案+宣纸 token（#0e0d0c/#171614/#f3efe8/#9c958c/#e8dfd2）；不要紫/金光/霓虹/emoji；折角纸是记不是装饰（`.kami-card-folded`/`.kami-slip`）；动效走合成线程（motion.ts FLIP；不给 left/top/width 做动画）；**新增动画必须进 prefers-reduced-motion**；鼠标优先。
- **queryKey 纪律**：身份敏感键用 `credentialTag(cookie)` 指纹；setQueryData/invalidate 的键必须与 useQuery **逐字一致**（TD-23 反例已修，queryKey 一致性 lint + RTL 家族测试双防线）。
- **zustand selector**：返回 filter/map 新数组会因引用不等无限重渲染——选稳定引用 + useMemo 派生。
- 品牌资产只动 `public/og.jpg`、`public/x-banner.jpg`、`public/favicon.svg`。
- 文档纪律：docs/ 已随 git 追踪（2026-09-17 起，27 份），改代码顺带提交 docs 变更；CHANGELOG 记用户可见变化。

## 4.9 高频陷阱

| 陷阱 | 说明 |
| --- | --- |
| KAMI_ROOT | resolveKamiRoot 兜底 cwd；跨目录启动落错位置；e2e 靠仓库外临时根隔离 |
| masonry 常量三处 | MASONRY_MIN_COL（TS）、--masonry-min（CSS 变量）、minmax(170px,1fr) 字面量必须同步（iOS 旧 WebKit 兼容）；手机单列阈值 MASONRY_SINGLE_COL_MAX=480 亦然 |
| 双层缓存 TTL | 已抽单一常量（TD-27 ✅），改缓存时长跟常量走 |
| 缓存键参数集 | 新增过滤参数必须进 sourceCacheKey 的 payload（fanbox 缺 hideAi 是前车之鉴，单测锁） |
| 设置段白名单三处 | 新增「要同步」的设置字段必须同时进：store partialize → backup.ts BackupSettings+parse → backup-client snapshotSettings（smartFolders 漏采事故：字段存在于类型却从未同步，拉取还清空本地，#151 修+回归测试；tagAliases #155 接线即按此清单三处齐动） |
| 跨端拉取空列表 | applySegment 对结构性列表有「字段缺失保留本地」守卫（现覆盖 smartFolders/watchArtists/tagAliases/authorAliases 四族——authorAliases 守卫 2026-09-17 #158 才补，此前的升级窗口已丢过数据）——新增同类列表字段时沿用该模式，别让旧载荷清空新字段 |
| Turbopack 动态 fs | 运行时才定界的动态路径（`.data` 下、Chrome 探测目录）必须内联 `/*turbopackIgnore: true*/`，否则 `next build` 警告且可能整仓进产物；现存 8 处（media-cache.server.ts/browser-login.server.ts），加新的动态 fs 读时照抄 |
| ~~快照 jsonb 白名单~~ | ✅ #144 改 information_schema 逐表枚举；仅枚举失败回退 `{"payload"}` 并 `[db-snapshot:jsonb]` 告警 |
| guest 决策 | 任何新 /api 路由都要**显式决策 guest 标记**（TD-20 教训）；改 guest 面必须同步 e2e/guest-tier.spec.ts |
| Windows | scripts 直调 next JS 入口绕 cmd 空格路径；改 scripts 需三平台验证 |
