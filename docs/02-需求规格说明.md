# 02 — 需求规格说明（逆向还原）

> 基线 `main@75e7de0`（含 bd1f28c）。本项目无需求文档存档，本章从代码、页面、接口与数据库反向还原。

## 2.1 系统解决什么问题

在**不把图站凭据交给浏览器直连**的前提下，用一台自托管服务聚合多个图站：统一浏览/搜索/看图/收藏/下载体验，隔离上游反爬（代理、UA、缓存），并把个人设置与收藏目录跨浏览器、跨设备同步。原始需求线索见 README 与 docs/comments.md（「纸匣」隐喻：看中的作品收进自己的纸盒）。

## 2.2 业务角色

| 角色 | 形态 | 能做什么 | 依据 |
| --- | --- | --- | --- |
| 主人（登录用户） | 应用账号开启（默认）且已登录 | 全部功能：个人面（纸匣读写、会话绑定、登录中转、账号同步）+ 公开内容面 | data-plane.server.ts:34-47 |
| 访客 | 应用账号开启但未登录 | 公开内容面：浏览/榜单/搜图数据（/api/source）、图片（/api/media）、社交操作、反向搜索、榜单只读；凭据由浏览器随请求体自带，不落服务端 | next-route.ts:5-8、e2e/guest-tier.spec.ts |
| LAN 匿名设备 | 账号关闭形态（`VITE_AUTH_ENABLED=false`） | 凭 24 字节配对令牌访问全部数据面（三通道：header / ?token= / cookie） | lan-token.server.ts:49-79 |

图站账号（Pixiv/FANBOX/Danbooru）不是系统角色，而是主人/访客随身携带的**凭据**（访客存 localStorage + 请求体；主人另有 HttpOnly 镜像 cookie）。
