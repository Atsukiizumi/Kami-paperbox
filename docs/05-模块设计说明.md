# 05 — 模块设计说明

> 基线 `main@75e7de0`（含 bd1f28c）。11 个核心模块各一节，统一模板；其余模块见 01 号清单表。配图：[模块关系图](diagrams/模块关系图.md)、[时序图](diagrams/时序图.md)、[状态图](diagrams/状态图.md)。

## M1 上游适配层（src/lib/upstream/）

**职责/目标**：把 5 个图站的非官方接口统一成 17 种 op 的判别联合返回（WorkCard/详情/画师/动图 meta）。**入口**：dispatch.ts `dispatchFetch(FetchInput)`。
**核心结构**：`FetchInput`（zod 判别联合，source.ts:20-113）→ `FetchOk` 19 种返回。**外部依赖**：pixiv.net / fanbox.cc / yande.re / konachan(.net 兜底，TD-11) / danbooru（Basic+固定 UA `Mozilla/5.0 gallery-dl/1.27.0`，策略性伪装）。
**业务规则**：R18 判定 `xRestrict>0||sl>=4||sexual>0`，loli 类无条件拉黑（pixiv.ts:26-39）；AI 判定 `aiType===2`+12 标签（pixiv-feed.ts:43-68）；booru BLOCKED_TAGS 22 词（booru.ts:75-97）；翻页用**过滤前**条数判定（TD-12）；Pixiv 日榜未公布窗口三类判定才回落（pixiv.ts:95-149）。
**正常/异常流**：见 04.1/04.2；UpstreamError→502。**关键配置**：DANBOORU_UA、PIXIV_RANK_MODES、BOORU_FEEDS。
**风险**：解析器随上游改版脆断（R-01，已有固定样本测试）；danbooru 全走 curl 通道慢（PER-10）；pixivUser 翻页全量重拉 profile/all（PER-9）。
**修改注意**：新增 op 必须同时动 fetchSchema/dispatch/返回联合（never 穷尽检查会拦）；booru 改动跑 mapping.test.ts 固定样本。

## M2 媒体代理管线（upstream/media.ts + media-cache/media-gate）

**职责**：唯一取图通道：白名单→盘缓存→单飞→并发闸→流式上限→落盘。**核心规则**：MEDIA_HOSTS 11 域 + MEDIA_SUFFIXES 9 后缀白名单（SEC-08 注：后缀匹配放行任意子域）；48MB 上限、8MB 落盘上限（PER-8）；fanbox/搜图引擎不落盘；出站 immutable 7d。
**异常**：429/503 退避、404 透传、413/断流、abort→204、单飞被首调用方掐断各自重拉。
**风险**：单飞绑定首调用方 cookie（访客形态松动，TD-40）；isPrivateIp 覆盖面自认不足（SEC-08，白名单为主防线）。
**修改注意**：放宽白名单前必须先把私网判断改成解析后判断（SEC-08 修复方案）。

## M3 出站通道与代理（curl-fetch.server.ts + proxy.server/proxy-url）

**职责**：全部上游 HTTP 的物理层：undici ProxyAgent 池（connect 15s/headers 45s/16 连接）→ 3 败熔断 10min → curl 子进程降级（--max-time 40、临时目录 body/headers 交换）。**代理优先级**：saved(.data/proxy.json) > config > env；resolveKamiRoot 是全后端 .data 定位基准（12 层 walkUp 识别标志文件，兜底 cwd——从任意目录启动会落错位置）。
**风险**：curl 依赖系统可执行文件；JSON 路无 AbortSignal/总超时（TD-28）；curl 每请求 mkdtemp/rmSync 同步 IO。
**修改注意**：动机注释（:4-9）解释了为什么必须连接池——改动前先读。

## M4 会话与凭据（browser-login*.ts + site-identity* + session-cookies）

**职责**：图站凭据的解析/组装/探测/镜像。PHPSESSID 正则判定登录态；fanbox 可复用 pixiv 会话（双 cookie 头）；额外发 x-userid 头。HttpOnly 镜像 cookie 三枚（kami_pixiv/kami_fanbox/kami_danbooru，maxAge 30 天）由 /api/sessions 写。
**规则**：访客串被 sanitize 丢弃；cred-tag FNV-1a 指纹替代 cookie 原文进 queryKey（SEC-04 产物）。
**风险**：cookie 无 Secure（SEC-06 取舍）；sessions/whoami/login-browser 的访客放行已补（bd1f28c，镜像 per-browser）。

## M5 应用账号与访问闸（src/lib/auth/）

**职责**：better-auth（邮箱密码、secret 落 .data/auth-secret.json 防重启掉登录、trustedOrigins 动态含 Host）+ withDataPlane 三态闸（同站校验→会话/访客 guest 标记/LAN 令牌 sha256+timingSafeEqual）。
**外部依赖**：PGlite（kysely 方言，LazyDriver 串行单连接）或 Postgres。
**风险**：DNS rebinding 取舍（SEC-13）；rateLimit 与 sync 同站校验已补（bd1f28c）；残余见 12 号。
**修改注意**：guest 标记改动必须同步 e2e/guest-tier.spec.ts 预期。

## M6 账号同步与加密（account-sync.ts + crypto-box.ts + backup*）

**职责**：四段 LWW 同步 + 信封加密。KEK=PBKDF2(账号密码, 服务端固定 salt, 210k)，raw key 仅 sessionStorage；三道凭据守卫（无 KEK 不推密文冲掉/密文无 KEK 跳拉/plain credsOmitted 保留本地）。备份 v2 同一 CipherBox 容器（口令派生不可导出 key）。
**风险**：legacy 明文落库（SEC-14/TD-25，待修）；LWW 时钟偏移（跨设备并发无向量钟）。TD-21（密文拉取覆盖凭据）已修：脏标记 + mergeCredentialsOnPull 本地非空保留 + 合并后补推（bd1f28c）。
**数据表**：user_sync_segments / user_sync_meta /（legacy）user_sync。
**修改注意**：凭据不变量写在 account-sync.ts 头注释——改动前核对守卫族不破（无 KEK 不推密文 / 密文无 KEK 跳拉 / plain credsOmitted 保留 / 脏标记合并，SENSITIVE_SETTINGS_FIELDS 七字段有单测锁集）。

## M7 纸匣存储（vault-store.server.ts + vault.ts + persist-files + vault-query/vault-index）

**职责**：收藏库。服务端 SQLite（works/pages 双表 + 索引 source/author/saved_at）+ 文件 `files/{source}/{id}/{n}.{ext}`；浏览器 IndexedDB 镜像（kami-vault v2，meta/blobs 两 store）；查询为全量读出+内存过滤（索引只加速排序）。
**写协议**（TD-08）：tmp 暂存→BEGIN IMMEDIATE 事务→rename→清旧。key 格式 `^[a-z]+source:[A-Za-z0-9_-]{1,80}$` 禁点号防穿越。
**风险**：磁盘无界不参与水位（TD-31）；patch 读-改-写非事务；浏览器/服务端 meta 最终一致无冲突检测。
**修改注意**：put 协议的崩溃安全论证在 :202-300 注释，动结构前先读。

## M8 下载队列（queue-runner.ts + queue-retry.ts + store.ts useQueue）

**职责**：收藏/下载的执行面。并发 1-4、退避 4/8/16s 封顶 3 次、用户态错误不重试（策略纯函数单测）；Web Locks 保证跨标签单执行者 + BroadcastChannel 镜像状态；BroadcastChannel 名 `kami-queue`。
**状态机**：pending→running→done/failed(→retry scheduled)→final；canceled。
**风险**：fetchBlob 90s 硬超时无重试（TD-29）；queue persist 只存状态不存 Blob（重载后需重拉）。

## M9 榜单归档（ranking-store.server.ts + ranking-archive.ts）

**职责**：booru 榜快照（浏览器侧读写 API + 服务端 SQLite upsert）。id=`site:period:date`；损坏行容错；打开失败停用归档（但无冷却，TD-39）。JST 日期工具（jstYesterdayCompact）也供 pixiv 回落使用。
**依赖**：`node:sqlite` DatabaseSync（实验性 API，R-11）。

## M10 反向搜索（reverse-search*.ts + prepare-search-image）

**职责**：三引擎上传搜图。SauceNAO JSON 优先（hide=0 不让源站预藏）、ascii2d 双跳（色+特征）session 8min、IQDB multipart；结果去重合并、URL 回链本站。
**限流**：引擎间隔预约制（pace()），等待 >12s 抛错换引擎建议；三引擎并发时整体放大（R-12 注记）。

## M11 前端壳与状态（app-shell + store.ts + providers + browse-cache/work-cache）

**职责**：全局布局（顶栏/侧栏/移动底栏）、首页保活与滚动恢复、6 个 zustand store（settings v10 persist / queue / history v2 / tag-lexicon / tag-catalog / vault-index 内存）、React Query 约定（staleTime 30min、身份敏感键带 credentialTag、乐观更新 patchCachedWork）。
**关键机制**：水合同步门防 SSR 错位；三层浏览缓存 hydrate/subscribe；AccountSyncBridge/LanTokenGate 全局挂载。
**风险**：AppShell 全局引首页（PER-13）；首页双渲染路径（保活 vs children）；hydrate 补刷三路并发（PER-14）；user 页 setQueryData 键错（TD-23）；vault 页远端异常未捕获（TD-38）。
**修改注意**：queryKey 与 setQueryData/invalidate 的键必须逐字一致（work.$source.$id.tsx:148-154 注释是正面范例，user.$id.tsx:109 是反例）。

## 纸匣智能库（2026-09-13，feat/vault-smart-library）

- **dHash 查重**：收藏入库即对首页算 64-bit 感知哈希（`src/lib/dhash.ts`，jpeg-js/pngjs 解码，webp 跳过）；扫描 API 补算老库存并按汉明距离（≤10）并查集聚类（`src/lib/vault-dedup.ts`）；忽略对持久化在 `vault_dup_dismissed`，候选组不落库、按哈希现场重算。个人面路由 `/api/vault/dedup`。
- **组合检索**：`vault-query.ts` 的 `filterVaultItems` 增 tags（任一命中）/month（YYYY-MM）谓词；`vaultTags`/`vaultMonths` 派生选项。
- **智能文件夹**：`SmartFolder = {id, name, query}` 存设置段（zustand persist + 备份往返 + 账号同步段），纸匣侧栏套用/保存/删除。
- **统计**：`/vault/stats` 客户端聚合 meta 出分布三图与按月时间线；存储占用走 `GET /api/vault/stats/storage`（works.bytes SQL GROUP BY）；查重状态卡显示哈希覆盖率。
- 设计与计划：`docs/superpowers/specs/2026-09-12-vault-smart-library-design.md`、`docs/superpowers/plans/2026-09-13-vault-smart-library.md`。
