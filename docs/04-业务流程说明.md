# 04 — 核心业务流程说明

> 六大核心流程。每个流程给出触发/前置/输入/处理/分支/数据变化/输出/异常/回滚。流程图集中在 [diagrams/核心业务流程图.md](diagrams/核心业务流程图.md)，时序细节见 [diagrams/时序图.md](diagrams/时序图.md)。

## FP-1 浏览信息流（三层缓存协作）

| 项 | 内容 |
| --- | --- |
| 触发 | 用户进入 `/`（或切图源 tab、翻页、改搜索词/开关/日期） |
| 前置 | 无（访客可用）；推荐/关注/FANBOX 流需对应图站 cookie |
| 输入 | `op` + 站点参数 + `safeMode/hideAi` + 当前账号 cookie（进 queryKey） |
| 处理 | ①浏览器创建 QueryClient 时同步 `hydrateBrowseCache`（localStorage `kami-browse-v1`，键前缀 home-*，24h 内有效）→ ②react-query 发 `POST /api/source` → ③服务端 zod 校验 → `unstable_cache`（1800s，tag=source:{key}）→ `.data/source`（30min，sha256(参数+uid)）→ ④ miss 时 `dispatchFetch` 打源站（upstream.server）→ 归一化为 `WorkCard[]` → 逐层写回 |
| 判断分支 | `fresh:true` 跳过两层缓存并 revalidateTag；安全模式在源站参数与本地映射双层过滤；hideAi 只对 pixiv（ai_type=1）+ 本地 aiType 过滤 |
| 数据变化 | 命中即无上游流量；miss 时写 `.data/source/*.json`；booru 榜单首次拉到后自动 `PUT /api/rankings` 存档（index.tsx:316-321） |
| 状态变化 | 无业务状态；queryKey 含 cookie/safeMode，切账号即天然换缓存 |
| 输出 | `FetchOk`（items + nextPage 或 cursor） |
| 异常 | localStorage 超配额→整体放弃（browse-cache.ts:96-100）；上游失败→400 + toast；「Missing queryFn」历史 bug 已修（仅挂载键后台补刷，CHANGELOG Unreleased） |
| 回滚 | 无需回滚；缓存层各自独立，坏一层退一层 |

## FP-2 图站登录中转（puppeteer 收割会话）

| 项 | 内容 |
| --- | --- |
| 触发 | 设置→账号点「登录」，或三步向导（onboarding） |
| 前置 | 本机有 Chrome/Chromium（puppeteer-core 不自带浏览器）；缺包时提示 `pnpm i`（browser-login.server.ts:510-511） |
| 输入 | `{site: "pixiv"\|"fanbox"}`；过程中的鼠标/键盘/文本事件流 |
| 处理 | 临时 profile（mkdtemp）→ 恒 headless Chrome（980×720，反自动化检测参数，可挂代理）→ CDP screencast JPEG 帧存入单例 `job.frame` → 前端每 280ms 轮询 `GET /api/login-browser?frame=1` 画 canvas，输入事件 `POST {action:"input"}` 回传 → 服务端每 700ms `Network.getAllCookies` 找合法 `^\d{1,12}_[A-Za-z0-9._-]{8,}$` 会话（访客令牌丢弃）→ pixiv 再跳首页确认头像昵称；fanbox 完成 `/auth/start` 回转 |
| 判断分支 | 同站点已有 busy job→直接复用快照；异站点→报错；4 分钟 deadline 内未收到有效 cookie→error |
| 数据变化 | 完成后 `applyLoginSession` 写 zustand 当前账号 → `syncSessions()` POST `/api/sessions` 发 HttpOnly 镜像 cookie（30 天） |
| 状态变化 | 单例状态机 `idle→launching→waiting→done/error`（时序图见 diagrams/时序图.md） |
| 输出 | `{pixiv, fanbox, pixivProfile, fanboxProfile}` 快照（**含 cookie 明文**，安全影响见 SEC-02） |
| 异常 | 无帧 >1.2s 用截图兜底；页面拿不到 profile 时服务端 `resolveIdentities` 补 |
| 回滚 | 取消动作 `stop=true` + closer；finally 恒删临时 profile、关浏览器 |

## FP-3 下载 / 收入纸匣（队列 → 三层归档）

| 项 | 内容 |
| --- | --- |
| 触发 | 卡片按钮 / 详情页「下载」「收入纸匣」；合集页整包（循环入队） |
| 前置 | 队列未满（80 条）；纸匣镜像到文件夹需已授权目录（未授权自动走应用内目录） |
| 输入 | `enqueueWork(work, kind: "download"\|"vault")`；`flyPaperToQueue` 纸片动效 |
| 处理 | 单飞串行循环（项间 sleep 400ms）：`loadWork`（POST /api/source 拿详情）→ `collectWorkFiles` 逐页 fetch `/api/media`（90s 超时；ugoira 下载 zip→解帧→gifenc 编 GIF，失败存 zip）→ `archiveWork`：**用户文件夹优先**（FS Access API，路径模板 `{author}{date}{title}...`，非法字符清洗、拒 `..`）→ 首页算 SHA-256 → 写 IDB meta（未进文件夹时连 blobs 一起写）→ 未进文件夹时 `PUT /api/vault`（FormData 上传像素，服务端 SQLite+文件）→ `rememberVaultKey` 点亮折角 |
| 判断分支 | 文件夹写入失败/未授权→全部降级应用内路径；kind=download 且未进文件夹→逐页触发浏览器下载 |
| 数据变化 | 用户文件夹文件 / `.data/vault/files/{source}/{id}/` / IDB `kami-vault`（meta+blobs）/ `.data/vault/vault.sqlite`（works+pages） |
| 状态变化 | QueueItem：`queued→running→done\|error`（progress/total 逐页回写） |
| 输出 | toast + 队列页进度；VaultMeta（relativePath/sha256/origin） |
| 异常 | 无自动重试（失败标 error 可手动重试）；刷新中断→resumeQueue 把 running 复位 queued；文件夹写非原子（进程中断可能留半文件，由巡检发现） |
| 回滚 | 失败项不留半索引（先文件后 meta）；重复入队同 key 只升级 kind 不重复占位；巡检 `rescanFolderHashes` 发现文件被替换→`patchVaultMeta({replaced:true})` 标笺条 |

## FP-4 应用账号与设置同步

| 项 | 内容 |
| --- | --- |
| 触发 | 设置→账号注册/登录（Better Auth email/password）；登录后任何设置变化 |
| 前置 | 应用账号已登录（`/api/account/sync` 是唯一强制鉴权的业务端点） |
| 输入 | `BackupFile` JSON：`settings`（含全部图站 cookie、API key）+ `vault` 目录 + `lexicon/catalog` + `history` + `proxyUrl`，≤2MB |
| 处理 | 推：AccountSyncBridge 订阅 useSettings，4s 防抖 POST 整份；拉：登录/启动时 GET，`remoteExportedAt > marker.syncedAt` 或换账号才应用，应用后设 5s 静默窗防回写 |
| 判断分支 | 服务端 upsert `user_sync`（PK user_id）整载荷覆盖 |
| 数据变化 | 服务端：user_sync 行 + PGlite 内存库；落盘：`.data/kami-db-snapshot.json`（30s 看护 + 写后 500ms） |
| 状态变化 | localStorage `kami-account-sync` 同步水位 marker |
| 输出 | 换浏览器登录即恢复各图站 Cookie、词表、纸匣目录、历史 |
| 异常 | 强杀进程丢最近 0.5–30s 写入（代码注释自认）；payload 除 exportedAt 外无 schema 校验 |
| 回滚 | 无版本历史——**整载荷 LWW**，多设备并发后写者覆盖先写者（全量覆盖，不可回滚）；单设备可用设置→备份手动导出兜底 |

## FP-5 以图搜图

| 项 | 内容 |
| --- | --- |
| 触发 | `/search` 页拖图/粘贴/选文件 |
| 前置 | 图片 ≤8MB、类型白名单 jpeg/png/gif/webp/bmp |
| 输入 | 浏览器预处理后的 JPEG（最长边 768px、q0.82、≤250KB 直传）+ safe + 可选 SauceNAO key |
| 处理 | `Promise.all` 并发三引擎：SauceNAO（multipart POST，JSON 优先 HTML 兜底解析）、ascii2d（先 GET 首页拿 csrf+cookie jar（8min TTL）再 POST，再抓 bovw 特征页）、IQDB（multipart POST） |
| 判断分支 | 单引擎失败不炸整体（limited/error 分组展示）；403/429/503 或 cloudflare/captcha 关键词→「被风控」标注；safeMode 过滤 IQDB explicit/questionable 结果；loli/shota 词组结果直接丢弃 |
| 数据变化 | 无持久化（no-store）；引擎缩略图可走 /api/media 代理（不落盘） |
| 输出 | 按引擎分组的结果列表；命中外链经 `workFromUrl` 反解为站内跳转 |
| 异常 | SauceNAO 等待 >12s 直接报错提示换 IQDB；限速参数见 kami.config.json throttle.search |
| 回滚 | 无状态，无需回滚 |

## FP-6 热榜归档回看

| 项 | 内容 |
| --- | --- |
| 触发 | 浏览页 booru 日/周/月榜首屏拉取成功（自动）；`/rankings` 页手动清理 |
| 前置 | 无 |
| 输入 | `{site(仅 booru), period, date, items≤200}` |
| 处理 | `PUT /api/rankings` → SQLite `snapshots` 以 `site:period:date` 为主键 upsert；GET 按 id/site+period 列表；DELETE 按 id/site |
| 数据变化 | `.data/rankings/rankings.sqlite`（不设上限） |
| 输出 | `/rankings` 页按站/日期回看历史榜单卡片 |
| 异常 | Vercel 形态不可写盘→getRankingStore 返回 null 当不可用 |
| 回滚 | 删除即清；Pixiv 不入库（浏览页日期直接拉原站历史榜） |

## 异常分支专述（跨流程）

1. **上游 Cloudflare**：Danbooru 匿名 403→提示配账号（Basic 凭据 + 强制 curl）；Konachan.com `!res.ok`→同路径切 konachan.net 镜像重试，成功后自动回 .com。**盲区**：200+HTML 挑战页不会触发镜像回退（upstream.server.ts:901 只判状态码），会直接报「源站暂时拒绝访问」。
2. **代理熔断**：undici 池连续 3 次失败→10 分钟窗口内全部走 curl（避免双份超时），窗口结束自动回池。
3. **媒体限流**：仅 pximg/fanbox 域过并发闸（默认 6，现配 5）；429/503 重试 1 次（500ms 退避）；48MB 硬上限。
4. **浏览器刷新**：浏览列表 localStorage 先画（≤24h）→ 30min 后台补刷；队列 running→queued 续跑；文件夹授权句柄在 IDB `kami-folder` 跨刷新保留。
