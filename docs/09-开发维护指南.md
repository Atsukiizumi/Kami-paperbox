# 09 — 开发维护指南

## 9.1 权威约定（来自 AGENTS.project.md，产品宪法级）

- 品牌基调：日本纸工房（墨黑 `#0e0d0c` / 宣纸 `#f3efe8`）；禁止紫/金光/霓虹/emoji；标题锁定「Kami 纸匣」；空态用 PaperMark/EmptySheet；笺条用 `.kami-slip` 不堆 Badge。
- 动效只走合成线程（motion.ts FLIP），禁止 left/top/width 动画；新动画必须进 `prefers-reduced-motion`。
- **下载/入纸匣必须 enqueueWork，禁止旁路另存**；动效名 `flyPaperToQueue`。
- Tag：Booru 显示中文、请求发英文；Pixiv/FANBOX 不套词表；搜索空格分多 tag（FANBOX 除外）。
- Cookie 只经 browser-login 通道；**真实 PHPSESSID 禁止进仓库/测试/截图/changelog**。
- 站点逻辑进 `src/lib/*`，界面进 `src/components` / `src/routes`；文件头注释写「作用、用法、为什么」。
- 用户可见行为变化写 CHANGELOG 并开 PR（用户说不要 PR 时听用户的）；版本号不随手改。

## 9.2 常见改动指南

### 新增图站（以新增 booru 系站点为例）

1. `src/lib/types.ts`：扩 `Source`（及 `BooruSite` 若适用）。
2. `src/lib/sites.ts`：SITE_LIST、原站链接生成。
3. `src/lib/booru.ts` 或新适配文件：origin、feed 映射、tag/榜单端点。
4. `src/lib/upstream.server.ts`（UC）：进 dispatchFetch 的对应分支（booruList/booruPost/booruPool）。
5. `src/lib/source.ts`：fetchSchema 若新增 op 需加判别分支（typecheck 会逼你补全 FetchOk）。
6. 前端：site-switcher、useSettings.tab 类型、（可选）词表与身份探测。
7. 测试：booru.test.ts 补映射用例；qa-booru-fix.mjs 加冒烟。

### 新增页面

1. 组件写 `src/routes/xxx.tsx`（TanStack 风格文件名或普通名均可）。
2. 薄壳 `app/xxx/page.tsx`：`"use client"; export { XxxPage as default } from "@/routes/xxx";`
3. 侧栏/底栏入口：app-shell.tsx；如需保活（返回不丢滚动）参考 app-shell.tsx:262-277 的 hidden 保活模式。
4. 站内链接一律 `kami-link.tsx` 的 `Link to="/xxx/$param"` 风格。

### 新增 API 端点

1. 实现 `src/routes/api/xxx.ts`，导出 `GET/POST`，用 `withRequest` 包装。
2. **必须**接 `runAuth(request)`（auth/middleware.ts:34）或明确注释为何豁免——当前仓库的教训是 13 个端点只有一个接了。
3. 校验用 zod（参考 source.ts 的判别联合风格）；出参统一 `{ok:true,...}` / `{ok:false,error}`。
4. 薄壳 `app/api/xxx/route.ts` re-export，`export const dynamic = "force-dynamic"`。

### 新增需跨设备同步的字段

进 BackupFile：`collectBackup`（backup.ts）+ `applyBackup`（backup-client.ts）两处同步加；否则「同步了但没恢复」。注意 2MB 上限。

### 新增数据库表

只加 `migrations/NNNN_name.sql`（不递归，勿放 auth/ 子目录）；PGlite 运行时与 build 迁移都会自动应用；破坏性变更需自备回滚说明（当前无 down 机制）。

## 9.3 验证流水线（本地）

```bash
npx tsc --noEmit        # 类型（注意：scripts/、server/ 不在 include 内）
pnpm test               # scripts 单测 + src/lib 34 个显式清单测试
pnpm lint
node scripts/browser-smoke.mjs http://127.0.0.1:8080 ./screenshots/smoke.png   # 双视口冒烟（路径要显式传）
node scripts/qa-*.mjs   # 场景级 QA（需 dev server 已起；qa-account-sync/qa-ugoira 等）
```

已知坑：**新增 `*.test.ts` 不会自动进 `pnpm test`**——test 脚本是手工清单，目前已有 10 个测试文件漏跑（见 10 文档），加测试必须同步改 package.json:24。

## 9.5 陷阱清单（分析中实证过的）

1. `app/` 下页面是薄壳——改 UI 别只改 app/，实际组件在 `src/routes/`。
2. `server/middleware/`、`scripts/grok-pwa-plugin.mjs`、`app-env-plugin.mjs`、`swallow-abort-plugin.mjs`、`src/lib/multiplayer/` 是 **Vite/Nitro/模板遗留死代码**，改它们对运行无影响（但 grok-pwa-shared.mjs 被 brand-check 引用，删前先看依赖）。
3. queryKey 内嵌 cookie/safeMode——改 key 结构要评估 localStorage `kami-browse-v1` 旧数据兼容（hydrateBrowseCache 只认 home-* 前缀）。
4. zustand persist 版本是 10，带 migrate；改 settings 结构要 bump version 并写迁移。
5. 出站新代码必须走 `outboundFetch`；直连 fetch 会绕过代理/熔断，用户挂代理时直接失败。
6. 媒体域名白名单（MEDIA_HOSTS/MEDIA_SUFFIXES）与「是否落盘」是两张表，加新图站 CDN 两个都要改。
7. Windows 本机跑 browser-smoke / preview.mjs 前先看 8.6：多处假设 Linux 沙箱。
8. `pnpm-lock.yaml` 被 gitignore 而 Dockerfile 用 package-lock.json——装依赖两套锁，发布前确认你改的是哪套。
