# 11 — 代码质量评估

> 基线 `main@75e7de0`（含 bd1f28c）。~250 个源文件（src 230+ / scripts 14 / e2e 3），无 AI 生成模板味，整体高于个人项目均值。

## 11.1 可读性

- **命名**：中英混合一致（模块英文、注释/文案中文）；`use*` hook、`*FromX` 解析器、`.server.ts` 后缀语义清晰。
- **注释**：文件头三段式（作用/用法/为什么）是全仓约定；「为什么」注释密度高且真实（curl-fetch.server.ts:4-9 连接池动机、media.ts:3-6 SSRF 自认、cache-watermark:8-10 为何不用 instrumentation）。
- **文件组织**：平铺 150 文件靠命名前缀聚簇（pixiv-*/vault-*/tag-*/reverse-search-*），可找性尚可但无目录边界。
- **方法/类长度**：巨文件集中在 UI：settings.tsx 827、index.tsx 778、artwork-card.tsx 580、work.$source.$id.tsx 489、store.ts ~470。服务端模块普遍 <400 行且职责单一。
- **魔法值**：多数抽了常量（MEDIA_HOSTS/BLOCKED_TAGS/PIXIV_RANK_MODES）；残留少量内联（如 8192/200/80 上限已进 zod 注释化）。
- **重复代码**：as* 四件套 ≥7 处复制（TD-32）；decodeHtmlEntities 两套（TD-37）；masonry 最小列宽三处（9.4 节）。

## 11.2 面向对象 / 类型设计

非 OOP 风格：模块导出纯函数 + zod 推断类型。SOLID 以「模块级 SRP + 判别联合 OCP」达成——新增 op 站点不改既有分支（never 穷尽检查=编译期强制开闭）。封装良好（快照/水位/单例均有模块边界）；继承/多态不适用。类型纪律强：unknown 清洗工具全覆盖上游 JSON，无 as any 滥用【基于源码推导，tsgo 门禁兜底】。

## 11.3 复杂度

- 无 God Class（upstream.server.ts 1257 行上帝模块已在 TD-01 拆为 upstream/ 六模块 + 桶导出）。
- 遗留热点：settings.tsx 9 分区一文件（hash 路由内部模拟）；artwork-card.tsx 承担卡片全部交互（580 行但内聚）；store.ts 的 useSettings 字段 30+（persist v10，migrate 有冗余分支 TD-39）。
- 深嵌套少；booru URL 拼装分支多但已被固定样本测试锁定。

## 11.4 异常处理

- 架构级清晰：UpstreamError→502 / 用户态→400（S7）；29 处 `[模块:操作]` console.warn。
- 仍存在的静默吞错：apply-session.ts:29 `.catch(()=>undefined)` 与 store.ts:297 `if(!res.ok) return`（TD-20 修复后已非 401 盲区载体，但仍无用户提示）；vault.tsx:55-76 listServerVault 未捕获（TD-38）。db-snapshot 恢复失败行已重试+隔离上报，不再只 warn（bd1f28c）。
- 重试语义分层明确（媒体退避 / 队列退避 / 无重试的 fetchBlob，TD-29）。

## 11.5 资源管理

- curl 临时目录 finally rmSync；undici 池挂 globalThis 单例；登录 job 4 分钟超时 + 凭据一次性消费；objectURL revoke 有复核（PER-3 修复）；ImageBitmap/Canvas 在 ugoira 用后显式释放路径完整【基于源码推导】。
- 弱点：sweepCache 全同步 IO（PER-11）；无 FinalizationRegistry 类兜底（可接受）。

## 11.6 结论

高于个人项目均值的真实工程：类型纪律、注释文化、崩溃安全设计、测试锚点四处亮点突出。扣分项集中且可修：UI 巨文件、工具复制、静默吞错尾部、平台遗留半死代码（TD-33/34）。评分见 16 号（代码质量 7/10）。
