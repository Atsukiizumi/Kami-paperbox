## 长期（1 年以上）：演进方向

| 方向 | 内容 | 触发条件 |
| --- | --- | --- |
| 多用户/家庭化 | 若需求从单用户走向家庭多账号：workbox 鉴权、per-user vault 隔离、配额 | 出现真实多用户需求前不动（当前所有单例设计都以此省成本） |
| 可观测性 | 结构化日志（pino）+ 请求 id 贯穿 UI→API→上游；上游健康面板（每站最近错误/延迟） | 上游对抗（R-01）排查成本明显上升时 |
| 上游适配韧性 | 解析器快照测试流水线（定期抓真实响应脱敏入库）；站点能力探测降级面板 | R-01 第二次大改版后 |
| 数据库演进 | 若 PGlite 快照窗口不可接受：迁移到 better-sqlite3（native，需装权限）或常驻 Postgres | 数据量/写入频率显著增长 |
| 部署形态收敛 | 官方支持形态收敛为「本机 + Docker」两条；Vercel 路径正式移除或改造（serverless 与 .data 假设冲突） | 出现部署需求时 |
| DevOps | 镜像自动构建（GHCR）、compose 一键升级脚本、备份定时提醒 | 用户群扩大 |
