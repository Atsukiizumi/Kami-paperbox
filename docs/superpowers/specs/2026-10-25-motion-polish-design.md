# Kami 纸匣：丝滑动效设计与分阶段计划

日期：2026-10-25。状态：用户已确认动效方向，实施计划待审阅。此次交付是计划与独立交互示意，产品代码尚未修改；示意的接受不等于正式实现的批准。

## 目标与依据

用户要求：「我想给网站加丝滑动画，你负责指定计划」，并选择增加可交互示意。

让浏览、选图、展开大图、入队这条现有路径更连贯：点下就响应，变化有来由，快速反向操作能接上当前画面。沿用日本纸工房的视觉语言，重点是「轻拿、展开、归位」。用户已确认这一方向；具体数值与分期仍是本次规划的建议，待实施计划评审。

成功的样子：反复切筛选、鼠标快速掠过卡片、打开后立刻关闭灯箱，画面连续而且操作始终有效；关闭应用内「动画效果」后，状态立即到达终点。

## 范围

本轮方案覆盖统一动效基座、浏览网格重排、图片揭示、悬停预览、选中滑块、既有入队反馈、弹层开合和灯箱手势衔接。

不增加业务功能，不改下载通道、持久化 schema、主题包或外壳版式；不引入动画依赖，不更换组件库。跨路由「卡片飞进详情」共享元素转场、全站惯性滚动、鼠标跟随、3D 翻页和新的自动循环效果暂不纳入。它们会扩大导航和渲染范围，对这一轮的核心目标帮助较少。

## 观感与参数

保留现有墨黑书案、宣纸配色、字体与排版。动效只负责解释用户刚做的动作，不对所有分区依次播放入场。静态页首首次绘制不额外延迟；加载好的图片立即可见可点。

| 用途 | 目标节奏 | 幅度与表现 |
| --- | --- | --- |
| 按压确认 | 按下 80ms，松开 150ms | 小控件缩至 0.97；文字输入与拖动手柄不缩放 |
| 卡片悬停 | 150ms | 原位轻抬约 2–3px；保留手绘态原有微歪，避免 clean 态现有 10px 大幅抬升 |
| 小菜单、提示、选中背景 | 150ms | 2–4px 或不位移，退出更轻 |
| 对话框、抽屉 | 展开 220ms，收起 150ms | 4–8px + opacity；方向与触发位置一致 |
| 网格重排、预览、灯箱展开 | 250ms | 从当前视觉位置接向新位置；灯箱收起 150ms |
| 单张图片由骨架揭示 | 150ms | 只淡入，不再让整张图慢慢缩回；缓存命中不重播 |
| 飞纸入队 | 400ms | 延续现有纸片轨迹；任务立即入队，动画随后反馈 |

统一沿用 `cubic-bezier(0.22, 1, 0.36, 1)`。这些是首轮评审值，示意页用于判断节奏；最终微调交给实施者在实机观感下完成，不能因此扩大场景或改变业务行为。

## 分阶段交付

### 第一批：统一基座与关停（P0）

目的：让同一操作只由一个动画控制，开关真正覆盖 CSS 与 JS。

- 保留 CSS token；JS 从计算样式读取对应时长与曲线，SSR / 不支持 WAAPI 时直接呈现终态。避免再维护一套逐渐漂移的 JS 常量表。
- 扩展现有 `motion.ts` 的生命周期约定：起播前读 `motionEnabled`；播到一半关闭开关时立即清理当前 UI 动画、临时 DOM、`will-change` 和退出计时器，并完成当前状态转换。
- 只登记并操作本次动效工具创建的动画与临时层，不能通过 `document.getAnimations()` 全量取消媒体、第三方组件或其他未拥有的动画。
- 中断后从当前可见状态改向，不先跳回初始关键帧。正常完成、取消、卸载三条路径都清理，`finished` 的取消拒绝必须被处理。
- CSS 过渡登记 `.kami-xfade` 或已有 `html[data-motion="off"]` 规则；JS 路径不能靠 CSS 的 `animation: none` 来关 WAAPI。
- 关停只取消 UI 补间和装饰反馈；拖拽/捏合仍然直接跟手，业务图像中的 GIF / Ugoira 播放维持现有独立语义。

交付门槛：关掉开关后没有新 UI 补间，进行中的弹层立即到达正确终态；再次开启不会重播历史动作。

### 第二批：浏览网格连续重排（P0）

目的：去掉一条已知会每帧触发布局的动画路径，先解决大量图片下的基础连续性。

- 保留 `packJustified`、直接子节点的 `data-aspect`、`.kami-card-media`、稳定作品 key 和现有浏览页挂载保留行为。
- 在一次打包内批量读取旧视觉矩形，写入最终 left/top/width/height 与容器高度，再批量读取新矩形；只给可视区域及近邻的存量卡片播放 transform FLIP。几何属性允许一次设置，不允许逐帧补间。
- 分离 transform 所有权：位置外层负责 FLIP；卡片内层负责 hover；图片揭示只控制媒体 opacity。现有 IO 入场不能与位置 FLIP 同时写同一个节点的 transform。
- 进入视口的卡片只播放一次轻揭示；已显示卡片在返回浏览、缓存恢复、追加下一页时不重播。追加数据只处理新增项，整批换站继续沿用容器 key 重置。
- 连续改密度、缩放窗口、筛选换数据时合帧执行，以最新目标为准；无有效尺寸、离屏或新增项直接落到最终几何。
- 容器高度一次落位，保持浏览滚动锚点；不把整个网格做 scale 来假装高度变化。纸匣的 CSS 列瀑布流不替换为此算法。

交付门槛：卡片最终位置和旧算法一致，现有比例不失真、文字不残留缩放；尾部追加不让前面作品重新入场；返回浏览保住当前位置。

### 第三批：高频交互精修（P1）

目的：把不同控件中零散的时间、位移和加载表现收成一套。

- 图片揭示用短淡入；保持现有预热、媒体车道、重试和内存命中语义，不为等待动画延迟图片请求或内容展示。
- 悬停预览延续「同一封面长大」；高清图未好先用已显示缩略图，不出现空白放大框；快速进出从当前进度反转，卸载、滚动导致锚点失效时安全收起。
- Tabs / ToggleGroup / 导航选中背景的几何先更新，背景层通过 transform 过渡；不同宽度项不能通过逐帧 width/height 过渡实现，也不能把标签文字一起拉伸。首挂载直接显示选中状态。
- 复用 Dialog / Dropdown / Popover / Select / Tooltip 的已有进出类，统一退出节奏并保留原组件的焦点管理和 Escape 行为。
- 入队后沿用 `flyPaperToQueue`，目标从当前可见且尺寸有效的队列入口中选择；没有可见目标则保留现有 toast。业务成功先发生，装饰动画失败不能影响入队。连续入队最多保留三张在途纸片，超过时合并视觉反馈，toast / 队列计数仍准确。
- 飞纸只表示「已入队」，不提前显示「已收入纸匣」折角或下载完成；折角和完成状态仍以原业务结果为准。

交付门槛：快速切项、快速进出预览、连续点入队时可立即操作，没有堆积的旧动画或持续增长的临时节点。

### 第四批：灯箱开合与手势衔接（P1）

目的：让开合有空间来由，让拖拽与捏合立即跟手。

- 拆开外层进出、内层缩放平移与图片揭示：外层负责淡入和轻展开；手势期间内层 transform 不做时间补间；双击、缩放按钮等离散操作才用短过渡。
- 仍用现有灯箱和相邻页预热；切页立即切换到目标页的加载状态，不保留上一张冒充当前页，不要求手势滑动新增换页行为。
- 将固定卸载定时器与实际退出生命周期对应；中途重新打开可以取消退出。关动画时直接设置可见状态并取消等待，后台标签页恢复也不能卡在透明层。
- 缩略图条的程序化定位在动效关闭时改成即时定位；滚动锁、现有键盘行为和焦点返回保持正确。
- 这一批使用原位淡入/轻展开，不承诺卡片与灯箱的跨节点共享元素 morph。后者需单独验证长图、视频与不同裁切比例。

交付门槛：单指拖拽、双指缩放、按钮缩放各用正确节奏；100ms 内开关反向操作不闪、不留下拦截层；退出后页面可以正常滚动。

## 验收方法与顺序

正式实施前先在同一台设备记录原版基线；示意页仅用于评审观感，不能作为正式应用性能或回归结果。

1. **基础行为**：现有类型检查、单元/组件测试和构建通过；对新增的关停/取消协议补小范围回归测试，对多场景组合用浏览器验证，不写逐行复刻实现的测试。
2. **确定性动效场景**：使用固定、无敏感凭据的图卡数据，覆盖 200 张加载后列表、追加 40 张、切换密度/视口、快速 A→B→A、预览开关、飞纸目标不可见和卸载；不依赖真实图站的网络速度评估动画。
3. **开关矩阵**：启动时 off、播放中 on→off、off→on；JS / CSS / 灯箱定时器 / 程序化平滑滚动全部检查。核对状态终点、可点击性和临时元素释放。
4. **浏览器观感**：桌面 Chrome、Firefox、Safari / iOS Safari（可用的真实环境为准，Playwright WebKit 结果单独标明），390px 与 1280px；浅/深主题、clean/hand、desk/rail/zen 抽样核对。触屏不依赖 hover 暴露主操作。
5. **性能证据**：录制同样操作序列，在相同设备、数据、视口下比较；目标为 60Hz 屏幕接近 60fps，重点确认动画稳定段没有由自定义布局补间导致的逐帧 Layout，没有新增 >50ms 长任务。图片解码、网络等待与动画成本分别记录，不能仅凭截图宣称丝滑。
6. **生命周期**：连续开关 30 次后在途 UI 动画数和临时纸片数回归零，退出灯箱后 overflow 恢复，无未处理 promise 拒绝；浏览返回位置与缓存不回退。

建议的正式验证入口：`pnpm typecheck`、`pnpm test`、`pnpm build`，再执行定向动效 E2E 与现有关键路径回归。当前环境没有全局 `pnpm`，实施时先检查仓库已有的包管理入口；本轮不安装依赖，也没有宣称这些正式检查已执行。

## 拆分、依赖与回退

建议四个小 PR，与上面四批对应，顺序为「基座 → 网格 → 交互 → 灯箱」。基座完成后才允许依赖其关停/清理协议。每批更新用户可见行为的 CHANGELOG，遵守现有 PR 规则；本轮只保留提案，不改 CHANGELOG、不发 PR。

每批独立验收，不一次全站铺开。紧急情况下应用内动画开关是即时停用手段；代码回退按 PR 反向撤回。没有存储迁移，关闭或回退动效不能改写队列、作品或浏览缓存。

实施者可以决定：内部函数和类名、组件层包裹方式、测试夹具实现、±30ms 的局部观感校准。不得自行扩大到新业务功能、跨路由过渡、全站滚动接管或改掉应用的动效偏好规则。

## 技术参考

- [web.dev：高性能 CSS 动画](https://web.dev/articles/animations-guide)：优先 transform / opacity，避免触发布局/重绘的逐帧属性动画，will-change 按需使用并释放。
- [MDN：Element.animate](https://developer.mozilla.org/en-US/docs/Web/API/Element/animate)：返回 Animation，适合登记和取消自己创建的动画。
- [MDN：Animation.cancel](https://developer.mozilla.org/en-US/docs/Web/API/Animation/cancel)：取消播放会拒绝当前 finished promise，需处理取消分支。
