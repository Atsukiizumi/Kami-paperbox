# 06 — 数据库设计说明

> 基线 `main@75e7de0`（含 bd1f28c）。E-R 图见 [ER图](diagrams/ER图.md)，数据流向见 [数据流图](diagrams/数据流图.md)。四套并行存储：(A) Postgres/PGlite 关系库（账号+同步）；(B) node:sqlite ×2（vault、rankings）；(C) 文件系统 `.data/`（缓存与快照）；(D) 浏览器 IndexedDB ×2 + localStorage。

## 6.1 架构选择

- **后端选择**：`DATABASE_URL` 非空白 → Postgres（pg Pool，一进程一池，int8/date 类型对齐）；否则 PGlite **纯内存实例**（不用 dataDir——WASM 实例强杀可损坏目录，electric-sql/pglite#327），持久化由 JSON 快照承担（db.ts:118-126、db-snapshot.server.ts）。
- **迁移**：PGlite 在 `getSql()` 首次调用时读 `migrations/` 顶层（**不递归**，`auth/` 子目录是「未开启登录不应用」的 opt-in 模板，两份 0001_auth.sql 逐字节相同）；Neon 在 build 后 `scripts/migrate.mjs` 执行（无连接直接跳过）。`_migrations` 表按 **basename** 记账。无 down 脚本（回滚靠代码回滚，schema 不回退）。
- **快照**：public 全表动态枚举（除 _migrations）+ FK 拓扑排序恢复 + 逐行 on conflict do nothing；500ms 防抖 + 30s 看护 + 写后显式 scheduleSnapshotDump 补偿；restore 失败行尾部重试一轮后**隔离落盘** `.data/kami-db-snapshot.restore-failed.json`，主快照照常演进（bd1f28c）。

## 6.2 表结构全量清单

### A. Postgres / PGlite（migrations/）

**user**（Better Auth，0001_auth.sql:19-27）：`id text PK`、`name text NOT NULL`、`email text NOT NULL UNIQUE`、`emailVerified boolean NOT NULL`、`image text NULL`、`createdAt/updatedAt timestamptz NOT NULL`（createdAt 默认 CURRENT_TIMESTAMP）。

**session**（:29-38）：`id text PK`、`expiresAt timestamptz NOT NULL`、`token text NOT NULL UNIQUE`、`ipAddress/userAgent text NULL`、`userId text NOT NULL FK→user(id) ON DELETE CASCADE`、时间戳同上。索引 `session_userId_idx`。

**account**（:40-54）：`id text PK`、`accountId/providerId text NOT NULL`、`userId text NOT NULL FK→user(id) ON DELETE CASCADE`、`accessToken/refreshToken/idToken text NULL`、`accessTokenExpiresAt/refreshTokenExpiresAt timestamptz NULL`、`scope text NULL`、`password text NULL`（邮箱密码通道）、时间戳。索引 `account_userId_idx`。**(providerId,accountId,userId) 无唯一约束**，靠 Better Auth 约定。

**verification**（:56-63）：`id text PK`、`identifier/value/expiresAt NOT NULL`、时间戳。索引 `verification_identifier_idx`。

**user_sync**（0002，legacy 过渡）：`user_id text PK`、`payload jsonb NOT NULL`、`exported_at bigint NOT NULL`（毫秒）、`updated_at timestamptz default now()`。**无 FK**（应用层 scope）。

**user_sync_segments**（0003，现行）：PK 复合 `(user_id, segment)`，segment ∈ {settings, vault, lexicon, history}；`payload jsonb NOT NULL`、`exported_at **text** NOT NULL`（毫秒字符串，route.ts:136 `String(exportedAt)`）、`updated_at timestamptz`。**与 0002 的 bigint 类型不一致（TD-30）**。

**user_sync_meta**（0003）：`user_id text PK`、`kdf_salt text NOT NULL`（base64，`on conflict do nothing` 保证固定）、`updated_at`。

**_migrations**（代码建表）：`name text PK, applied_at timestamptz default now()`。

### B. SQLite vault（.data/vault/vault.sqlite，vault-store.server.ts:22-49）

**works**：`key TEXT PK`（`{source}:{id}`，parseVaultKey 校验禁点号）、`source/id TEXT NOT NULL`、`title TEXT NOT NULL default '无题'`、`author TEXT NOT NULL`、`author_id TEXT NOT NULL default ''`、`tags TEXT NOT NULL default '[]'`（JSON，≤80）、`page_count INTEGER NOT NULL`、`saved_at INTEGER NOT NULL`（epoch ms）、`bytes INTEGER NOT NULL`、`relative_path/folder_label TEXT NULL`。索引：source/author/saved_at。

**pages**：PK 复合 `(key, page)`（page 0 起）、`ext/mime TEXT NOT NULL`、`bytes INTEGER NOT NULL`、`path TEXT NOT NULL`（相对 `files/{source}/{id}/{n}.{ext}`）。

### C. SQLite rankings（.data/rankings/rankings.sqlite，ranking-store.server.ts:27-37）

**snapshots**：`id TEXT PK`（`{site}:{period}:{date}`）、`site/period/date TEXT NOT NULL`（period ∈ daily/weekly/monthly）、`fetched_at INTEGER NOT NULL`、`items TEXT NOT NULL`（WorkCard[] JSON，PUT 侧截 200）。索引 `(site, period, date)`。无 TTL 无上限（TD-31）。

### D. 文件系统（.data/，storage.md 为官方口径）

| 路径 | 结构 | TTL/清理 |
| --- | --- | --- |
| source/{sha256}.json | `{at, body}`（键=op 参数+safeMode/hideAi+账号 id/guest） | 30min，读时惰性删 |
| media/{sha256}.bin + .json | 字节 + `{type, at}` | 7 天；>8MB 拒存；部分域名排除 |
| kami-db-snapshot.json | `{at, tables:{表:行[]}}` 全量 | 防抖合并 + 30s 看护 |
| vault/files/... | 收藏原图 | 永久（put 协议清未引用） |
| auth-secret.json / lan-token.json / proxy.json | 密钥/令牌/代理 | 永久 |
| rankings.sqlite | 见上 | 永久 |

水位治理只覆盖 media/source（默认 2048/512MB，kami.config 可调；每 50 写扫描，删至 80%）。

### E. 浏览器端

IndexedDB `kami-vault` v2（meta: keyPath key + bySource/byAuthor/bySavedAt 索引；blobs: `{key}#{page}`）；IndexedDB `kami-folder`（FS Access DirectoryHandle）。localStorage：kami-settings(v10)/kami-queue/kami-history(v2)/kami-tag-lexicon/kami-tag-catalog/kami-browse-v2(24h)/kami-account-sync-v2(marker)/kami-sync-kek(sessionStorage，raw KEK)。

## 6.3 数据关系（E-R 摘要）

- Postgres：user 1—N session、user 1—N account（均 FK CASCADE）；user 1—1 user_sync（legacy）、user 1—4 user_sync_segments、user 1—1 user_sync_meta（**均无 FK**，应用层按 requireUserId scope）。
- vault：works 1—N pages（key 关联，无声明式 FK）。
- rankings 独立无关联。

## 6.4 数据质量评估

| 检查项 | 现状 |
| --- | --- |
| 主键 | 全部代理键 text/复合，合理；vault key 兼具业务唯一性 |
| 外键 | 仅 Better Auth 三表有；同步三表无 FK（换取快照恢复灵活性，靠应用层） |
| 命名 | Better Auth camelCase（带引号）vs 同步表 snake_case 并存——两代约定 |
| 类型 | exported_at bigint/text 不一致（TD-30）；payload jsonb 合理 |
| Nullable | account 大量 NULL（OAuth 预留，邮箱密码只用 password）——可接受 |
| 审计字段 | created/updated 齐全；无创建人概念（单用户） |
| 软删除 | 无（删除即物理删，queue 有 canceled 态） |
| 状态字段 | 队列状态在浏览器 persist；库内无状态列 |

## 6.5 一致性机制

| 机制 | 位置 | 覆盖 |
| --- | --- | --- |
| UPSERT 幂等 | sync 三表 / snapshots / works | 重放安全 |
| 事务 | PGlite 迁移、vault BEGIN IMMEDIATE、Neon 迁移 | 应用查询无跨表事务需求 |
| 原子文件写 | tmp+rename（快照、auth secret、vault 页） | 崩溃安全 |
| LWW | 段粒度 exportedAt 比较 | **无版本向量/乐观锁**，时钟偏移风险 |
| 防并发 | globalThis promise 槽、迁移链序列化 | HMR/并发请求 |
| 快照窗口 | 500ms 防抖 + 30s + 写后补偿 | 强杀最多丢 30s（Better Auth 内部写路径无补偿） |

2. SEC-14/TD-25 legacy user_sync 整份明文 settings 可落库并随快照全表落盘。
3. ~~TD-22 restore 部分失败仍回写固化丢行~~ ✅ bd1f28c：失败行重试一轮后隔离到 `.data/kami-db-snapshot.restore-failed.json`，不再被主快照覆盖。
4. TD-31 rankings/vault 磁盘无界，不参与水位。
5. R-12 多进程/多实例下快照互踩无防护【需要确认当前部署是否永远单进程】。
