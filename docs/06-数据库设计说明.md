# 06 — 数据库设计说明

> 本项目有**四类持久化**：①Postgres（PGlite 内存 / Neon，经 migrations 管理）②node:sqlite（纸匣）③node:sqlite（热榜）④文件型（缓存/快照/JSON，不属 SQL，一并列出便于全貌）。E-R 图见 [diagrams/ER图.md](diagrams/ER图.md)。

## 6.1 Postgres 模式（migrations/，PGlite 与 Neon 同构）

### 表 `user`（应用账号主体）— migrations/0001_auth.sql:19-27

| 字段 | 类型 | 约束/默认 | 说明 |
| --- | --- | --- | --- |
| id | text | PK | Better Auth 生成 |
| name | text | NOT NULL | 显示名 |
| email | text | NOT NULL UNIQUE | 登录标识 |
| emailVerified | boolean | NOT NULL | 邮箱验证（本机形态恒 false） |
| image | text | 可空 | 头像 |
| createdAt / updatedAt | timestamptz | NOT NULL，createdAt 默认 now() | 审计字段 |

### 表 `session`（会话）— 0001_auth.sql:29-38

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | text | PK | |
| expiresAt | timestamptz | NOT NULL | 过期时间 |
| token | text | NOT NULL **UNIQUE** | 会话令牌（cookie 值的哈希载体） |
| ipAddress / userAgent | text | 可空 | 审计 |
| userId | text | NOT NULL **FK → user.id ON DELETE CASCADE** | 唯一真外键 |
| createdAt / updatedAt | timestamptz | NOT NULL | |

### 表 `account`（认证账号 / 凭据）— 0001_auth.sql:40-54

Grok 平台退出后 providerId 只剩 `credential`（邮箱密码单通道，password 为哈希）。userId FK → user.id ON DELETE CASCADE。

### 表 `verification`（一次性令牌）— 0001_auth.sql:56-63

identifier + value + expiresAt；索引 verification_identifier_idx。

### 表 `user_sync`（设置同步快照，旧单行格式）— migrations/0002_user_sync.sql

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| user_id | text | **PK** | 逻辑引用 user.id（无 FK） |
| payload | jsonb | NOT NULL | 整份 BackupFile（过渡期兼容读取；新推送走分段表） |
| exported_at | bigint | NOT NULL | 毫秒时间戳，LWW 比较基准 |
| updated_at | timestamptz | NOT NULL DEFAULT now() | |

### 表 `user_sync_segments`（分段同步，0003_user_sync_segments.sql）— TD-09/18 落地

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| user_id | text | **PK(user_id,segment)** | 逻辑引用 user.id |
| segment | text | 同上 | ∈ {settings, vault, lexicon, history} 四段 |
| payload | jsonb | NOT NULL | settings 段可为 CipherBox 密文（`{v:1,kdf:PBKDF2-SHA256,salt,iv,ct,iter}`）；其余段为明文数据 |
| exported_at | text | NOT NULL | 毫秒时间戳（字符串形态），**段级 LWW** 比较基准 |
| updated_at | timestamptz | NOT NULL DEFAULT now() | |

### 表 `user_sync_meta`（同步加密元数据）— SEC-03 第二刀

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| user_id | text | **PK** | 逻辑引用 user.id |
| kdf_salt | text | NOT NULL | 每用户一份 base64 盐；KEK = PBKDF2(账号密码, salt, 210k 轮)，登录时派生 |
| updated_at | timestamptz | NOT NULL DEFAULT now() | |

### 运行时表 `_migrations`（name PK, applied_at）— db.ts:128-130

迁移按文件名记账，`pendingMigrations` 排序跳过已应用（migration-plan.mjs:39-46）；`migrations/auth/` 子目录是模板副本，**不参与执行**（与顶层 0001_auth.sql 字节级相同，md5 一致）。

## 6.2 SQLite：纸匣（.data/vault/vault.sqlite）— vault-store.server.ts:22-49

**works**（目录主表）：key TEXT PK（`source:id`）、source/id/title/author NOT NULL、author_id TEXT DEFAULT ''、tags TEXT DEFAULT '[]'（JSON 数组，截 80 个）、page_count/saved_at/bytes INTEGER NOT NULL、relative_path TEXT（用户文件夹相对路径）、folder_label TEXT。索引：idx_works_source / idx_works_author / idx_works_saved。

**pages**（页明细）：(key, page) 复合 PK，ext/mime/bytes/path NOT NULL，path 为相对 vault 目录文件路径。**与 works 无外键**，靠 put/dropFiles 应用层同步（风险见 6.5）。

## 6.3 SQLite：热榜（.data/rankings/rankings.sqlite）— ranking-store.server.ts:27-37

**snapshots**：id TEXT PK（`site:period:date`）、site/period(daily|weekly|monthly)/date TEXT NOT NULL、fetched_at INTEGER NOT NULL、items TEXT NOT NULL（WorkCard JSON 数组，PUT 单快照截 200 条）。索引 idx_snap_site_period(site,period,date)。

## 6.4 文件型存储（非 SQL，全貌清单）

| 路径 | 内容 | 格式 | 写入时机 |
| --- | --- | --- | --- |
| `.data/kami-db-snapshot.json` | user/account/session/user_sync 四表全量（**不含 user_sync_segments/user_sync_meta，见 DQ-8**） | JSON，tmp+rename 原子 | 启动 dump + 30s 看护 + auth POST 后 500ms + sync POST 后 |
| `.data/source/{sha256}.json` | 列表缓存（30min，目录水位默认 512MB） | JSON | /api/source miss 回填 |
| `.data/media/{sha256}.{bin,json}` | 媒体缓存（7d，单文件 ≤8MB，目录水位默认 2GB） | 原始字节 + 元数据 | /api/media 命中回填 |
| `.data/proxy.json` + `kami.config.json` | 代理配置双写 | JSON | 设置保存代理 |
| `.data/auth-secret.json` | Better Auth 会话签名密钥（本地形态） | JSON，tmp+rename 原子 | 首次生成；与会话快照同生共死（重启不掉登录） |
| 浏览器 localStorage | kami-settings（含明文 cookie）/ kami-browse-v2（键含凭据指纹）/ kami-queue / kami-history / kami-tag-catalog / kami-tag-lexicon / kami-account-sync-v2 / kami-sync-kek（sessionStorage） | JSON | 各 store persist |
| 浏览器 IndexedDB | kami-vault（meta+blobs）/ kami-folder（目录句柄） | 结构化 | 归档/授权时 |

## 6.5 数据质量与一致性评估

**设计优点**

- PGlite/Neon 同一 migrations 源，双后端行为对齐（int8/date 类型归一化，db.ts:60-70）——预览与生产数据形状一致。
- 迁移原子（事务内应用+记账），构建期（migrate.mjs，pg）与运行期（db.ts，PGlite）双实现共享 pendingMigrations 纯函数（有单测）。
- db-snapshot 的 tmp+rename + 内容不变跳过，是崩溃安全的范本。
