## 13.2 当前风险与潜在瓶颈

> 状态（2026-09-10 两批后）：PER-4 ✅（inflightMedia 单飞，现住 `upstream/media.ts`）、PER-5 ✅（capStreamBytes 断流）、PER-1 ✅（`cache-watermark.server.ts`：每 50 次写惰性扫描，超水位按 mtime 淘汰到 80%；kami.config 的 cache.mediaMaxMb/sourceMaxMb 可配，默认 2GB/512MB）。PER-2 ✅（进度 200ms 节流 + 同值去重；卡片订阅本就布尔短路）、PER-3 ✅（分批渲染首批 60 / 续 40；封面 revoke 复核已在）。

| 编号 | 风险 | 位置 | 说明 | 建议 | 需验证 |
| --- | --- | --- | --- | --- | --- |
| PER-1 | 缓存目录无界 | .data/media、.data/source | 惰性删除只发生在「再次读到」，文件数只增不减 | 启动时后台扫描清理 + 总量水位（如 media 2GB） | 是（观察真实增速） |
| PER-2 | 队列进度高频重渲染 | queue-runner onProgress → useQueue patch → 50 张卡片各订阅 some()（artwork-card.tsx:70-74） | 下载 100 页作品时每页触发全列表重渲染 + kami-queue 同步写 localStorage | 进度节流（如 200ms）；卡片订阅改 selectors 细粒度；进度条独立轻组件 | 是（React Profiler） |
| PER-3 | 纸匣页无虚拟化全量加载封面 | vault.tsx:245-270 每卡 IDB blob + objectURL + new Image() | 大库（目录不设上限）时内存与 IDB 压力大 | objectURL 及时 revoke；首屏分页；虚拟列表 | 是 |
| PER-4 | 媒体层无 in-flight 去重 | media-cache.server.ts | 同 URL 并发（多卡片同图）重复打上游 | Map<url,Promise> 单飞（social CSRF 已有同款实现） | 否（低风险确定性改进） |
| PER-5 | 无 Content-Length 流式路径不复核 48MB | upstream.server.ts:1240-1249 | length===0 时流式转发，此后上限不再检查 | 流式累计字节超限即断 | 否 |
| PER-6 | PGlite 单连接排队 + 全表 JSON 快照 | pglite-dialect.ts:47-70、db-snapshot | 表小（单用户）无碍；快照是 O(表大小) 写 | 维持；若账号量级增长再议增量 | 否 |
| PER-7 | 登录中转轮询 280ms JPEG 帧转发 | session-relay.tsx | LAN 内可接受；公网部署会放大带宽。（09-12 注：访客打开中转因 401 无限空转的 bug 已随 TD-20 修复——非 2xx 快速失败，空转消失；280ms 通道带宽结论不变） | 已是 screencast 增量，维持 | 否 |

**不存在的问题**（澄清）：无 ORM 关系查询故无 N+1；SQL 均走索引（works 三索引、snapshots 复合索引、user_sync PK）；列表分页在源站侧完成。
