# 部署架构图

- **目的**：三种运行形态 + CI 流水线的物理视图。
- **基线**：`main@75e7de0`。

```mermaid
flowchart TB
  subgraph dev["形态 A：本机 dev/生产"]
    A1["pnpm dev / build+start<br>经 with-app-env 注入环境"]
    A2["Node 22 单进程<br>0.0.0.0:8080"]
    A3[(".data/（仓库根）")]
    A1 --> A2 --> A3
  end

  subgraph docker["形态 B：Docker 单容器"]
    B1["docker compose up --build<br>node:22-bookworm-slim 两阶段"]
    B2["runner: curl + chromium + noto-cjk<br>ENV PORT=8080 PUPPETEER_EXECUTABLE_PATH"]
    B3[("命名卷 kami-data:/app/.data")]
    B4["HEALTHCHECK: curl / 30s"]
    B1 --> B2 --> B3
    B2 --> B4
  end

  subgraph lan["形态 C：LAN 令牌（账号关闭）"]
    C1["build-arg VITE_AUTH_ENABLED=false"]
    C2["首启生成 24B 令牌<br>.data/lan-token.json"]
    C3["终端打印 http://ip:8080/#pair=token<br>三通道: header/?token=/cookie"]
    C1 --> C2 --> C3
  end

  subgraph ci["CI（PR + main push，并发去重）"]
    V["verify: tsgo → test → lint → build"]
    D["docker: buildx 构建不推送 (GHA 缓存)"]
    E["e2e: playwright chromium<br>e2e-server 隔离根"]
    V ~~~ D ~~~ E
  end

  LANDEV["手机/平板（LAN）"] -->|"形态 A/B/C 皆可"| A2
  LANDEV --> B2
```

**图解**：三形态共享同一个 `.data/` 语义（KAMI_ROOT 解析）；Docker 是唯一自带浏览器与字体的形态；LAN 令牌形态只是把数据面闸从「应用会话」换成「配对令牌」，其余不变。CI 三 job 见 08 号 8.4。

**风险点**：① e2e 本地复用已存 server 时隔离失效（TD-26）；② `.dockerignore` 未排除 kami.config.json（SEC-15）；③ 无专用健康端点（用 `/`）；④ Vercel 形态已实质废弃但 `.vercel/` 残留（16 号长期「部署形态收敛」）。
