# 系统架构图（分层视图）

- **目的**：展示进程内分层与每层的核心构件、层间调用方向。
- **涉及模块**：app/、src/routes、src/lib 全域。
- **基线**：`main@75e7de0`。

```mermaid
flowchart TB
  subgraph L1["UI 层（'use client'）"]
    pages["页面×11（src/routes）<br>浏览/搜索/详情/纸匣/队列/设置..."]
    comps["组件 60+（app-shell / masonry-board /<br>artwork-card / lightbox / ugoira-player...）"]
  end

  subgraph L2["Client 应用层"]
    rq["React Query（staleTime 30min·凭据指纹键）"]
    zst["zustand ×6（settings v10 / queue / history / lexicon / catalog / vault-index）"]
    srcc["source.ts（fetchSchema 19 op·唯一数据入口）"]
    qrun["queue-runner（Web Locks 单执行者）"]
    bc["browse-cache（localStorage 24h）"]
  end

  subgraph L3["API 层（app/api 薄壳 → src/routes/api）"]
    gate["withDataPlane 横切闸<br>Fetch-Metadata 同站 → 会话/访客/LAN 令牌"]
    zod["zod 判别联合校验"]
    err502["错误二分：Upstream→502 / 用户态→400"]
  end

  end

  subgraph L5["存储层"]
    db[("PGlite 内存库 / Postgres<br>+ JSON 快照 500ms/30s")]

  subgraph L6["基础设施层"]
    curl["curl-fetch（undici 池 16 连接<br>3 败熔断 10min → curl 子进程降级）"]

    crypt["crypto-box（PBKDF2 210k + AES-GCM）"]

  L1 --> L2 --> L3 --> L4 --> L5
  L4 --> L6
  L2 -->|"fetch /api/*"| L3
```

**图解**：依赖方向总体单向向下（UI→Client→API→Server→Storage/Infra）。三个横切件贯穿：withDataPlane（安全）、三层缓存（性能）、crypto-box（凭据）。薄壳层 app/ 只做 re-export，真实实现全在 src/routes 与 src/lib。

**风险点**：① AppShell（L1 壳）反向 import 首页实现，破坏了单向性（PER-13）；② L4 内 source-cache 与 unstable_cache 双层记账（TD-27）；③ L5 三库无跨库事务，一致性靠应用层协议（06 号）。
