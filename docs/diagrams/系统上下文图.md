# 系统上下文图（System Context Diagram）

- **目的**：一眼看清系统边界——谁用它、它依赖哪些外部系统、数据从哪来到哪去。
- **涉及模块**：整体（app/ + src/），不展开内部结构（那是架构图的职责）。
- **基线**：`main@75e7de0`。

```mermaid
flowchart TB
  subgraph people["使用者"]
    owner(["主人（应用账号登录·全功能）"])
    guest(["访客（未登录·公开内容面+绑定链路）"])
    lan(["LAN 匿名设备（账号关闭形态·配对令牌）"])
  end

  subgraph kami["Kami 纸匣（自托管 · Next.js 16 单进程 · 0.0.0.0:8080）"]
    app["Web UI（浏览/搜索/纸匣/队列/设置）<br>+ 12 条 /api/* 数据面"]
  end

  subgraph upstream["图站上游（非官方接口·逆向适配）"]
    pixiv["Pixiv（ajax/ranking.php）"]
    fanbox["FANBOX（api.fanbox.cc）"]
    booru["yande.re / konachan(.net 镜像兜底) / danbooru"]
  end

  subgraph search["搜图引擎"]
    engines["SauceNAO / ascii2d / IQDB"]
  end

  subgraph infra["基础设施"]
    proxy["可选 HTTP/SOCKS 代理"]
    pg[("可选 Postgres<br>（DATABASE_URL，缺省 PGlite 内存库）")]
    chrome["系统 Chrome/Chromium<br>（登录中转投屏）"]
    data[(".data/ 落盘根（KAMI_ROOT）<br>SQLite×2 + 快照 + 缓存 + 密钥")]
  end

  owner -->|"HTTPS 同源"| app
  guest -->|"HTTPS 同源（凭据随身·不落服务端）"| app
  lan -->|"HTTP + #pair= 令牌"| app
  app -->|"undici 池 / curl 降级（带凭据/UA/Referer）"| pixiv
  app -->|同上| fanbox
  app -->|同上（danbooru 走 curl+Basic）| booru
  app -->|"上传缩图（限流预约）"| engines
  app -.->|"经代理池出站"| proxy
  app -->|"账号库（有连接时）"| pg
  app -->|"puppeteer-core CDP"| chrome
  app -->|"全部持久化"| data
```

**图解**：三类使用者走同一入口；一切上游访问由服务端代劳（凭据/代理/反爬收敛在服务端）；持久化全部落在 KAMI_ROOT 的 `.data/`（或外接 Postgres）。访客与 LAN 形态的差异只在数据面闸的放行策略（12 号文档）。

**风险点**：① 上游全部是非官方接口，反爬升级即断（R-01）；② 默认绑 0.0.0.0，威胁模型必须包含不可信 LAN 设备（12 号）；③ 登录中转依赖系统浏览器存在；④ PGlite 形态的持久化依赖快照文件（强杀丢 0.5-30s 窗口）。
