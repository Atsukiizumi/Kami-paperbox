# 系统上下文图（System Context Diagram）

**图的目的**：界定系统边界——谁是外部实体、数据从哪来到哪去、哪些依赖不可控。
**涉及的模块**：整个 Kami 纸匣进程（作为单一系统单元）与其全部外部实体。

```mermaid
flowchart TB
    subgraph users["用户角色"]
        visitor["访客浏览器<br/>（LAN 内手机 / 平板 / 桌面）"]
        runner["运行者<br/>（部署与配置，通常同一人）"]
    end

    system(["Kami 纸匣<br/>Next.js 15 单进程<br/>0.0.0.0:8080<br/>浏览 · 搜索 · 反搜 · 队列 · 纸匣 · 账号同步"])

    subgraph boards["图站上游（逆向非官方接口）"]
        pixiv["Pixiv<br/>ranking/ajax API<br/>+ accounts.pixiv.net 登录"]
        fanbox["FANBOX<br/>api.fanbox.cc<br/>（付费内容需订阅会话）"]
        yande["yande.re"]
        kona["konachan.com<br/>（Cloudflare 高危，回退 .net 镜像）"]
        danbooru["Danbooru<br/>（匿名 403，需 Basic 凭据）"]
    end

    subgraph rs["以图搜图引擎"]
        saucenao["SauceNAO<br/>（可选 api_key）"]
        ascii2d["ascii2d<br/>（csrf + cookie 会话）"]
        iqdb["IQDB"]
    end

    infra["本机基础设施<br/>Chrome/Chromium（puppeteer-core 驱动）<br/>curl 可执行文件（兜底出站）<br/>用户文件夹（FS Access API）<br/>可选出站代理 http/socks5"]

    grok["Grok 平台（部署态才依赖）<br/>auth.grok.me 联邦登录 · gate.grok.me JWT<br/>connectors.grok.me（本项目未消费）"]

    visitor -->|"HTTP（同源 fetch）"| system
    runner -->|"kami.config.json / 环境变量 / 设置页"| system

    system -->|"服务端代理请求（Referer 伪造 / Basic / CSRF）"| pixiv & fanbox & yande & kona & danbooru
    system -->|"multipart 上传缩图"| saucenao & ascii2d & iqdb
    system -.->|"登录中转投屏 / 出站兜底 / 文件写入"| infra
    system -.->|"部署态应用登录"| grok
    pixiv & fanbox & yande & kona & danbooru -.->|"封面 / 原图像素（经 /api/media 落盘缓存）"| system
```

**图解说明**

- 浏览器**只与 Kami 纸匣通信**，从不直连图站——代理、防盗链、Cloudflare、凭据四类问题被整体移到服务端解决，这是系统存在的核心理由。
- 图站与搜图引擎都是**不可控上游**（逆向接口，随时可能改版/加固，见风险 R-01）。
- 虚线是「环境依赖」而非业务数据流：Chrome、curl、用户文件夹、代理都是本机资源，缺失时对应功能降级（登录中转不可用 / 兜底失效 / 镜像降级应用内目录）。
- Grok 平台仅在部署态参与登录；本机形态（当前主形态）完全不依赖它。

**风险点 / 注意事项**：系统默认监听 `0.0.0.0`，图中「访客浏览器」实际上可以是**局域网内任何设备**——安全评估（12 文档）的全部高危问题都源于这个边界的信任假设。
