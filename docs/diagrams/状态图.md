# 状态图（State Diagrams）

- **目的**：有明显生命周期的三类对象：下载队列项、登录中转 job、同步凭据脏标记。
- **基线**：`main@75e7de0`（含 bd1f28c）。

## 1. 队列项（queue-runner + queue-retry，浏览器侧）

```mermaid
stateDiagram-v2
  [*] --> pending: enqueueWork (去重 live 项)
  pending --> running: runQueue 取出 (并发 1-4)
  running --> done: 全页下载完成
  running --> canceled: 用户移除
  running --> failedRetry: 可重试错误 (网络/5xx)
  running --> failedFinal: 用户态错误 (不重试)
  failedRetry --> scheduled: 退避 4s/8s/16s (封顶 3 次)
  scheduled --> running: 到点重试
  scheduled --> failedFinal: 次数耗尽
  failedFinal --> pending: 用户手动重试
  done --> [*]
  canceled --> [*]
```

注：状态存 zustand persist（kami-queue，≤80 条只存状态不存 Blob）；跨标签由 Web Locks 保证单执行者 + BroadcastChannel 镜像。

## 2. 登录中转 job（browser-login.server，进程内单例）

```mermaid
stateDiagram-v2
  [*] --> starting: POST {site} (顶替旧 job)
  starting --> running: Chrome 启动成功
  starting --> error: 浏览器缺失/启动失败
  running --> running: 轮询帧/输入转发
  running --> done: PHPSESSID 匹配登录正则
  running --> error: 非 2xx 快速失败 (bd1f28c, 含访客 401)
  running --> timeout: 4 分钟无进展
  running --> canceled: {action:"cancel"}
  done --> [*]: credentials=1 一次性取走 (内存即清)
  error --> [*]
  timeout --> [*]
  canceled --> [*]
```

## 3. 同步凭据脏标记（bd1f28c 新增，localStorage kami-cred-dirty-v1）

```mermaid
stateDiagram-v2
  [*] --> clean
  clean --> dirty: 访客期改凭据 (指纹变化)
  dirty --> dirty: 持续改动
  dirty --> merged: 登录拉取 cipher 段<br>mergeCredentialsOnPull 本地保留
  merged --> clean: 补推 settings 成功 (clearCredsDirty)
  clean --> clean: cipher 拉取无脏标记 → 整段应用
  note right of dirty
    全局标记不分会话:
    本机最新凭据优先于远端 (有意取舍)
  end note
```

**图解**：三个状态机的共同设计取向——终态要么可恢复（failedFinal→手动重试）、要么可清理（凭据随 job 销毁）、要么自愈（脏标记推完即清）。

**风险点**：① 队列 persist 不存 Blob，重载后需重拉（设计取舍）；② 登录 job 单例互顶——并发开两个中转后者顶替前者【基于源码推导】；③ 脏标记跨设备并发不设防（LWW 时钟偏移，R-04）。
