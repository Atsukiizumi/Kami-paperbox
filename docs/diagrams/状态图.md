# 状态图（State Diagrams）

**图的目的**：三个有明确生命周期的对象。**涉及的模块**：M6（登录任务）、M7（队列项）、M3（媒体缓存条目）。

## 图 1：登录中转任务（browser-login 单例）

```mermaid
stateDiagram-v2
    [*] --> idle
    idle --> launching: POST {site}（无 busy job）
    launching --> waiting: Chrome 起来 + 登录页打开
    waiting --> waiting: 帧更新 / input 事件 / cookie 未达格式
    waiting --> done: 收到合法已登录会话 + 身份确认
    waiting --> error: 4min deadline / Chrome 崩溃 / 用户取消
    launching --> error: 启动失败（无浏览器/缺包）
    done --> idle: 快照被取走 + 清理（关浏览器删 profile）
    error --> idle: 清理完成
    note right of waiting
        互斥规则：同站 busy → 复用快照
        异站 busy → 报错
    end note
```

## 图 2：队列项（QueueItem，localStorage kami-queue）

```mermaid
stateDiagram-v2
    [*] --> queued: enqueueWork（≤80 条，同 key 去重）
    queued --> running: runQueue 取出（单并发）
    running --> running: 每页 patch progress
    running --> done: 全部页归档成功
    running --> error: 任一步失败（无自动重试）
    error --> queued: 用户手动重试 / 刷新后 resumeQueue
    done --> [*]: clearDone / clearAll
    error --> [*]: remove / clearAll
    note right of running
        刷新页面：running 复位为 queued（resumeQueue）
        下载与纸匣共用此状态机，kind 字段区分
    end note
```

## 图 3：媒体缓存条目（.data/media）

```mermaid
stateDiagram-v2
    [*] --> absent: 首次请求该 URL
    absent --> fresh: 拉取成功且 ≤8MB 且可落盘域
    absent --> memory_only: fanbox 域 / 搜图引擎域（策略禁落盘）
    fresh --> stale: 7 天 TTL 过（读时才发现）
    stale --> absent: 惰性 unlink（仅当再次读到）
    memory_only --> absent: 响应结束即弃
    note right of stale
        风险：无人再读的过期文件永不删除，
        目录无界增长（TD-07）
    end note
```

**图解说明**：三个状态机都由**单用户低并发**前提简化——登录任务全局单例、队列单并发、缓存惰性清理，都不需要处理竞态；一旦做多用户/多标签并发（长期路线），图 1 和图 2 的互斥语义需要重新设计（参考 16 文档触发条件）。

**风险点**：图 2 的 error→queued 依赖用户手动介入，长批量下载中一个失败不阻塞后续项（串行循环继续），但也不会自动补跑失败项。
