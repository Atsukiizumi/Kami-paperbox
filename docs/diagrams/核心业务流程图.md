# 核心业务流程图

**图的目的**：三个最关键流程的完整分支（含异常），对应 04 文档 FP-1/FP-2/FP-3。
**涉及的模块**：M1/M2/M3（浏览）、M6/M5（登录）、M7（归档）。

## 图 1：浏览信息流（FP-1，三层缓存）

```mermaid
flowchart TD
    start(["进入 / 或切源/翻页/改筛选"]) --> hydrate["浏览器：hydrateBrowseCache<br/>从 localStorage 同步灌入（24h 内有效）"]
    hydrate --> paint["首屏立即画本地缓存"]
    paint --> query["react-query 发 POST /api/source<br/>（queryKey 含 cookie/safeMode/hideAi）"]
    query --> zod{"zod 校验<br/>fetchSchema"}
    zod -->|"不合法"| err400["400 → toast"]
    zod -->|"合法"| fresh{"fresh:true?"}
    fresh -->|"是"| revalidate["revalidateTag 跳过两层缓存"]
    fresh -->|"否"| nextcache{"Next unstable_cache<br/>（1800s）命中?"}
    revalidate --> diskcache
    nextcache -->|"命中"| ret["返回 FetchOk"]
    nextcache -->|"miss"| diskcache{".data/source<br/>（30min）命中?"}
    diskcache -->|"命中"| ret
    diskcache -->|"miss"| upstream["dispatchFetch → 站点适配<br/>→ outboundFetch（池/curl）"]
    upstream --> upfail{"上游 OK?"}
    upfail -->|"非 2xx / 限流 / 挑战页"| fallback{"站点兜底"}
    fallback -->|"konachan 且 !res.ok"| mirror["切 konachan.net 镜像重试 → 成功则回 .com"]
    fallback -->|"danbooru 403"| hint["提示配 Basic 凭据<br/>（有凭据则强制 curl + Basic）"]
    fallback -->|"其余"| errup["UpstreamError→502<br/>其余→400（S7）"]
    mirror --> map
    upfail -->|"OK"| map["JSON → WorkCard[] 归一化<br/>（safeMode/hideAi/BLOCKED_TAGS 过滤）"]
    hint --> errup
    map --> booru{"booru 榜单?"}
    booru -->|"是"| archive["PUT /api/rankings 自动存档（截 200 条）"]
    booru -->|"否"| writ
    archive --> writ["写回 .data/source + unstable_cache"]
    writ --> ret
    ret --> merge["react-query 合并 → 30min 内不再发"]
```

**图解（2026-09-11 复核）**：异常分支覆盖了 400、上游失败、Konachan 镜像（200+HTML 挑战页也回退，TD-11 ✅）、Danbooru Cloudflare 四条路径；缓存命中路径完全不打上游。~~翻页启发式误判末页（TD-12）~~ ✅ 已改用过滤前原始条数判断。

## 图 2：图站登录中转（FP-2）

```mermaid
flowchart TD
    start(["设置→账号 点登录"]) --> mutex{"已有同站 busy job?"}
    mutex -->|"是"| reuse["直接复用快照"]
    mutex -->|"异站 busy"| busyerr["报错"]
    mutex -->|"否"| launch["临时 profile → 恒 headless Chrome<br/>（可挂代理）→ 导航官方登录页"]
    launch --> cast["CDP screencast JPEG 帧 → job.frame"]
    cast --> loop["循环：前端 280ms 轮询画帧<br/>+ POST input 事件（鼠标/键盘/IME）"]
    loop --> poll["服务端每 700ms 读全部 cookie"]
    poll --> valid{"出现合法已登录会话?<br/>^\\d{1,12}_[A-Za-z0-9._-]{8,}$"}
    valid -->|"是"| confirm["pixiv: 跳首页确认头像昵称<br/>fanbox: 完成 /auth/start 回转"]
    valid -->|"否"| deadline{"4 分钟到?"}
    deadline -->|"否"| loop
    deadline -->|"是"| timeout["status=error → 清理临时 profile"]
    confirm --> done["status=done（含会话+身份）"]
    done --> apply["applyLoginSession 写 zustand 当前账号"]
    apply --> sync["syncSessions → POST /api/sessions<br/>发 HttpOnly 镜像 cookie（30 天）"]
    sync --> whoami["refreshIdentities 刷新头像"]
```

**图解**：单例互斥是单用户假设的体现；「合法格式」过滤掉了访客令牌。轮询与快照端点均已过数据面访问闸（SEC-02 ✅）。**风险**：headless 反检测参数可能随 Chrome 升级失效（R-01 一类）。

## 图 3：下载 / 收入纸匣（FP-3）

```mermaid
flowchart TD
    start(["卡片/详情页点 下载 或 收入纸匣"]) --> full{"队列 < 80 条?"}
    full -->|"否"| reject["toast 拒绝"]
    full -->|"是"| enqueue["enqueueWork + flyPaperToQueue 动画<br/>（同 key 去重，仅升级 kind）"]
    enqueue --> runner["runQueue 单飞串行（项间 400ms）"]
    runner --> load["loadWork：POST /api/source 取详情"]
    load --> collect["collectWorkFiles：逐页 fetch /api/media（90s 超时）"]
    collect --> ugoira{"ugoira?"}
    ugoira -->|"是"| gif["拉 zip → 解帧 → gifenc 编 GIF<br/>失败回退存 zip"]
    ugoira -->|"否"| folder
    gif --> folder{"已授权用户文件夹?"}
    folder -->|"是"| write["按路径模板写文件夹<br/>（createWritable → close，非原子）"]
    folder -->|"否"| appvault["写 IDB blobs + PUT /api/vault<br/>（服务端 SQLite + files/，先删后写）"]
    write --> hash["首页算 SHA-256"]
    appvault --> hash
    hash --> meta["写 IDB meta + rememberVaultKey 折角"]
    meta --> dl{"kind=download 且未进文件夹?"}
    dl -->|"是"| browser["逐页触发浏览器下载"]
    dl -->|"否"| done(["done"])
    browser --> done
    runner -.->|"任一步失败"| errq["status=error + toast（可手动重试）"]
    hash -.->|"后续巡检 rescanFolderHashes<br/>文件被换/丢 → patch replaced=true"| meta
```

**图解（2026-09-11 复核）**：用户文件夹是第一优先落点，应用内目录只是兜底；SHA-256 巡检是事后一致性手段。服务端 vault 写已原子化（暂存+事务先行+rename，TD-08 ✅）；文件夹写走 FS Access createWritable（本身原子）。**剩余风险**：失败无自动重试、无跨标签页共享（M6 待做）；~~进度回写全列表重渲染（PER-2）~~ ✅ 200ms 节流。
