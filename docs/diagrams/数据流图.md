# 数据流图（DFD）

**图的目的**：追踪三类核心数据（列表 JSON、图像像素、凭据）在存储之间的流动与落点。
**涉及的模块**：M1/M2/M3/M5/M7/M8 与各存储。

```mermaid
flowchart LR
    subgraph browser_stores["浏览器存储"]
        ls_set["localStorage<br/>kami-settings（含明文 cookie!）"]
        ls_browse["localStorage<br/>kami-browse-v1（queryKey 含 cookie!）"]
        ls_q["localStorage<br/>kami-queue / kami-history / 词表"]
        idb_vault["IndexedDB kami-vault<br/>meta + 像素 blobs"]
        idb_folder["IndexedDB kami-folder<br/>目录句柄"]
        rq["react-query 内存<br/>（30min stale / 2h gc）"]
    end

    subgraph server_stores["服务端存储（.data/）"]
        src_cache["source/*.json<br/>（30min）"]
        media_cache["media/*.bin+json<br/>（7d，≤8MB/文件）"]
        vault_db["vault/vault.sqlite<br/>+ vault/files/"]
        rank_db["rankings/rankings.sqlite"]
        dbsnap["kami-db-snapshot.json<br/>（账号四表全量）"]
        usertable[("PGlite user_sync<br/>（内存，payload=jsonb）")]
        proxyjson["proxy.json + kami.config.json"]
    end

    upstream["图站上游"]
    page["页面组件"]
    api["本站 API"]

    ls_browse -->|"启动同步 hydrate"| rq
    rq -->|"dehydrate（700ms 防抖，16 查询×8 页）"| ls_browse
    page <--> rq
    page -->|"POST op + cookie(body)"| api
    api <--> src_cache
    api -->|"miss 时"| upstream
    upstream -->|"列表 JSON"| api
    api -->|"FetchOk"| rq

    page -->|"GET /api/media?u="| api
    api <--> media_cache
    media_cache -.->|"miss"| upstream

    page -->|"PUT /api/vault（multipart）"| api
    api --> vault_db
    idb_vault <-->|"封面读取：本地优先 miss 打 API"| page
    page -->|"归档写"| idb_vault
    idb_folder -->|"目录写 + 巡检 SHA-256"| page

    api --> rank_db
    ls_set -->|"collectBackup"| syncjson["BackupFile JSON ≤2MB"]
    ls_q --> syncjson
    idb_vault -->|"目录段（无像素）"| syncjson
    syncjson -->|"POST /api/account/sync（鉴权）"| usertable
    usertable -->|"30s/写后500ms"| dbsnap
    page -->|"POST /api/proxy"| proxyjson

    style ls_set stroke:#c0392b,color:#c0392b
    style ls_browse stroke:#c0392b,color:#c0392b
    style usertable stroke:#c0392b,color:#c0392b
```

**图解说明**

- **列表数据**走「上游 → API → 盘缓存 → react-query → localStorage」单向流，每层有独立 TTL（30min/1800s/30min/24h）。
- **像素数据**只在归档时进 IDB/磁盘；浏览态像素始终由 `/api/media` 代理（浏览器 HTTP 缓存 7d immutable）。
- 红色标出的三个节点是**凭据明文落点**（kami-settings、kami-browse-v1 的 queryKey、user_sync.payload）——SEC-03/04 的数据流证据。

**风险点 / 注意事项**：`kami-browse-v1` 会让已删除账号的 cookie 在 localStorage 残留至 24h 过期；备份导出（syncjson 落地文件）与 user_sync 同构，泄露面等同（12 文档）。
