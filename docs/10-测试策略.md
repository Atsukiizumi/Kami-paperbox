# 10 — 测试策略

## 10.1 现状盘点

**单测（node:test，`pnpm test` 两段）**

- scripts 段：glob 自动发现，9 个文件（with-app-env、migration-plan、brand-check、browser-smoke-verdict、check-auth-invariant、grok-pwa-plugin、preview、sign-out-plan、write-atomic）。
- lib 段：`node --experimental-strip-types --test <显式清单>`，**手工维护 34 个文件**。src/lib 实际有 44 个 `*.test.ts`。

**未被 `pnpm test` 执行的 10 个测试文件**（find 与 package.json:24 对比）：abort、page-thumbs、pixiv-profile、pixiv-search、ranking-archive、ranking-store、tag-catalog、tag-database、tag-lexicon、view-history。→ 必须手动 `node --experimental-strip-types --test src/lib/xxx.test.ts` 才跑，极易形成「测试存在但从未运行」的假绿。

**场景 QA（Playwright，手动）**：qa-account-sync（双浏览器账号同步全链路）、qa-booru-fix（konachan 兜底+hydration）、qa-browse-cache（过期缓存恢复）、qa-ugoira（动图播放字节级比对）；browser-smoke（双视口截图 + console 错误 + 基线 diff，输出 verdict JSON）。

**无**：正式 E2E 套件（无 playwright.config/test 目录）、覆盖率工具（无 c8/nyc）、契约测试（上游 API 改版靠解析器单测的固定样本兜）、负载/性能测试。

## 10.2 质量评价

**优点**：解析器与算法层抽离成纯函数使单测自然（masonry-flow、migration-plan、proxy-url、reverse-search 的 HTML 解析等都有实打实的断言）；qa-\* 是高质量的场景级验证（账号同步用两个浏览器 context 验证端到端）；browser-smoke 的基线 diff 能抓「上线后白屏」。

**短板**：测试清单手工漂移（上表）；无 CI 把 `typecheck+test+lint+build` 变成门禁；服务端模块（upstream/social/browser-login/vault-store）几乎无测试——最高风险的 1257 行上游适配层只有间接覆盖；无覆盖率基线，不知道「多少没测」。

## 10.3 建议测试矩阵

| 模块 | 测试类型 | 核心场景 | 优先级 |
| --- | --- | --- | --- |
| upstream 映射 | 单测（固定 JSON 样本） | 每站点每 op 的字段映射、safeMode/hideAi 过滤边界、R-18 拦截 | P0 |
| outbound 管线 | 单测 + 集成 | 无代理直连 / 池失败降级 / 熔断窗口 / curl 不可用报错 | P0 |
| 鉴权不变量 | 集成 | 每个端点未授权访问的预期行为（修复 SEC-01 的回归测试） | P0 |
| 队列/归档 | 单测（mock fetch） | 顺序、失败标错、resume、文件夹降级、路径模板非法输入 | P1 |
| 账号同步 | 集成（已有 qa-account-sync） | LWW 覆盖语义、静默窗、2MB 上限、payload 损坏 | P1 |
| 缓存 | 单测 | TTL 过期、fresh 击穿、key 稳定性（uid 不含 cookie） | P1 |
| 迁移 | 单测（已有）+ 新库冒烟 | 新迁移在空库/旧库上的幂等 | P1 |
| 瀑布流/动效 | 单测（已有） | 回归保持 | P2 |
| E2E 关键路径 | Playwright 配置化 | 浏览→详情→入队→纸匣出现；登录中转（需真 Chrome） | P2 |
| 快照恢复 | 集成 | 损坏 json / 部分表缺失时启动行为 | P2 |

## 10.4 立即可做的三件事

1. 把 lib 段测试改成 glob 自动发现（与 scripts 段一致），消灭清单漂移。
2. 建 GitHub Actions：PR 上跑 `typecheck + test + lint + build`（.github 目前只有 issue/PR 模板，零 CI）。
3. 给 upstream.server 的每个映射函数补固定样本单测（数据可从真实响应脱敏截取——注意 AGENTS.project.md 禁止真实会话进仓库）。
