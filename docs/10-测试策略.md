**单测（node:test，`pnpm test` 两段，均已 glob 自动发现）**

- scripts 段：`node --test "scripts/**/*.test.mjs"`，3 个文件（with-app-env 17 例、migration-plan 8 例、sign-out-plan 8 例）。

**场景 QA（Playwright，手动）**：qa-account-sync（双浏览器账号同步全链路）、qa-booru-fix（konachan 兜底+hydration）、qa-browse-cache（过期缓存恢复）、qa-ugoira（动图播放字节级比对）。

**CI（TD-03 ✅）**：.github/workflows/ci.yml 在 push main / PR 跑 `typecheck → test → lint → build` 四门禁，concurrency 取消同分支旧跑。

**无**：正式 E2E 套件（无 playwright.config/test 目录）、组件测试（无 RTL）、覆盖率工具（无 c8/nyc）、契约测试（上游 API 改版靠解析器单测的固定样本兜）、负载/性能测试。

## 10.2 质量评价

**优点**：解析器与算法层抽离成纯函数使单测自然（masonry-flow、migration-plan、proxy-url、reverse-search 的 HTML 解析等都有实打实的断言）；TD-01 拆分后 upstream/mapping.test.ts 用 8 例固定真实样本守住上游映射（R-01 对冲的核心资产）；qa-\* 是高质量的场景级验证（账号同步用两个浏览器 context 验证端到端）；CI 四门禁已成 PR 必经之路。

**短板**：服务端模块（social/browser-login/queue-runner/save-work）几乎无测试——登录中转 573 行只有类型守护；无覆盖率基线，不知道「多少没测」；qa-\* 未进 CI（需真实 Chrome 与网络，只能本地手动）；E2E 关键路径无框架化回归。
