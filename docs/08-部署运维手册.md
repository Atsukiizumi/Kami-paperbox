# 08 — 部署与运维手册

> 基线 `main@75e7de0`（含 bd1f28c）。配图：[部署架构图](diagrams/部署架构图.md)。落盘细节官方口径见 [storage.md](storage.md)。

## 8.1 环境要求

- Node ≥22（`node:sqlite` 实验性 API 要求；推荐 22 LTS）；pnpm 10.15.1（corepack）。
- 可选：系统 curl（出站降级通道）、Chromium/Chrome（登录中转，puppeteer-core 不自带浏览器；Docker 镜像内置）、Postgres（设 `DATABASE_URL` 即启用，否则 PGlite 内存库+快照）。

## 8.2 部署形态

| 形态 | 步骤 | 要点 |
| --- | --- | --- |
| 本机 dev | `pnpm i && pnpm dev` | 绑 0.0.0.0:8080（kami.config）；with-app-env 注入 `.grok/app-env.json` 的 VITE_*；Next16 需 allowedDevOrigins（已配） |
| 本机生产 | `pnpm build && pnpm start` | build 尾自动 `scripts/migrate.mjs`（无 DATABASE_URL 自动跳过，PGlite 启动自迁移）；**build 阶段不触碰数据库**（db.ts:250-251 显式跳过 production-build phase——2026-09-11 事故后加固） |
| Docker | `docker compose up --build` | 两阶段 node:22-bookworm-slim；runner 装 curl+chromium+noto-cjk；ENV PORT/HOSTNAME/PUPPETEER_EXECUTABLE_PATH；standalone 产物 + migrations + kami.config；命名卷 `kami-data:/app/.data`；HEALTHCHECK curl `/`（30s/5s/20s/3 重试）；`VITE_AUTH_ENABLED` 默认 "true"（TD-17 修复），ARG 可覆盖 |
| LAN 令牌形态 | 构建时 `--build-arg VITE_AUTH_ENABLED=false` | 数据面改走 24B 配对令牌（.data/lan-token.json；终端打印 `http://<ip>:8080/#pair=<token>`；三通道 header/?token=/cookie；泄露=删文件重启换新） |
| ~~Vercel~~ | 已实质废弃 | serverless 只读文件系统与 .data 假设冲突；遗留 .vercel/ 产物待清 |

## 8.5 运维要点

- **数据位置**：一切在 KAMI_ROOT 下 `.data/`（见 06 号 D 节）。备份 = 导出 JSON（设置页，可选口令加密 v2）+ 直接拷贝 `.data/`（停机后）。
- **日志**：stdout/stderr 的 `[模块:操作]` console.warn（29 处）+ lan-token/db-snapshot 的 console.log；无级别无集中收集（S7 最小版）。
- **健康检查**：Docker 用 `/`（无专用健康端点）。
- **升级**：拉新代码 → `pnpm i` → `pnpm build`（自动跑增量迁移，basename 字母序）→ 重启。**迁移无 down 脚本**：回滚 = 回代码 + 手工处理 schema 差异（历史未出现过不兼容 down 需求）。
- **故障恢复**：PGlite 损坏/丢快照 → 账号库回到最近快照（最差丢 30s）；恢复失败的个别行隔离在 `.data/kami-db-snapshot.restore-failed.json` 供人工处置，不再静默销毁（bd1f28c）；vault SQLite 与文件双自洽；缓存目录可整删（自动重建）。
- **磁盘治理**：media 2GB / source 512MB 水位自动淘汰；**vault 与 rankings 不在治理内**（TD-31），长跑实例需手动关注 `.data/vault` 与 `rankings.sqlite` 增长。

## 8.6 已知运维陷阱（本期核验）

1. e2e 本地 `reuseExistingServer`（!CI）复用已运行的普通 dev server 时，e2e 账号会写进真实 `.data`（TD-26）——跑 e2e 前确认 8080 未被占用或预期污染。
2. `.tmp-kami-root.txt` 误入库（含本机路径，无引用）应删除并 ignore（TD-33）。
3. `startup.sh` 引用已删除的 `scripts/preview.mjs`（`|| true` 兜底不致命；平台契约残留，TD-34）。
4. Windows：with-app-env 对 cmd 空格路径做了 JS 入口直调绕行（scripts 改动需三平台验证）。
5. 从非项目目录启动进程时 KAMI_ROOT 兜底 cwd，`.data` 会落到意外位置——用 KAMI_ROOT 显式指定。
