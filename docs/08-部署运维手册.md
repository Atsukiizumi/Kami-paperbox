# 08 — 部署与运维手册

## 8.1 编译与启动

| 命令 | 实际链路 | 用途 |
| --- | --- | --- |
| `pnpm dev` | `scripts/with-app-env.mjs` 注入 `.grok/app-env.json`（仅 VITE_ 前缀键）→ `next dev --hostname 0.0.0.0 --port 8080` | 开发 |
| `pnpm build` | `next build` → **`node scripts/migrate.mjs`**（有 DATABASE_URL 时对真库跑迁移；无则跳过 exit 0） | 生产构建 |
| `pnpm start` / `pnpm preview` | `next start --hostname 0.0.0.0 --port 8080`（两脚本完全重复） | 生产服务 |
| `pnpm kami` | 一键入口：缺依赖自动 `pnpm install` 后转发上述命令 | 便捷 |

环境要求：Node ≥ 22、pnpm 10.15.1；本机另需 **curl 可执行文件**（代理兜底/探测）与 **Chrome/Chromium**（登录中转；Docker 镜像已内置 chromium 并设 `PUPPETEER_EXECUTABLE_PATH=/usr/bin/chromium`）。Windows 下 with-app-env 用 `node node_modules/next/dist/bin/next` 直接调 JS 入口绕开 cmd 空格路径问题。

`VITE_AUTH_ENABLED` 决定应用账号三态（true=开启 email/pwd+OAuth；false=关闭，requireUserId 在无真库时返回 dev-user）。`.grok/app-env.json` 当前为 `{"VITE_AUTH_ENABLED":"true"}`。

## 8.2 三种部署形态

### A. 本机 / 局域网（主形态）

1. `pnpm i && pnpm build && pnpm start`
2. 访问 `http://<机器IP>:8080`（默认绑 0.0.0.0，手机/平板可用）
3. 数据全部落在项目根 `.data/`（详见 storage.md 与 06 文档 6.4）
4. 需代理时：设置页配置（写 `.data/proxy.json` + `kami.config.json` + env）或预设 `KAMI_PROXY`

### B. Docker

```bash
docker compose up --build   # 镜像 next standalone（node server.js）+ chromium + Noto CJK
```

- 数据卷：命名卷 `kami-data:/app/.data`（纸匣/缓存/快照全在内，容器重建不丢）
- **注意 1**：镜像构建时烧死 `VITE_AUTH_ENABLED=false` → Docker 形态无应用账号/同步功能
- **注意 2**：容器内访问图站需代理时，启用 compose 中注释掉的 `KAMI_PROXY`（示例指向 `host.docker.internal:7890`）
- 健康检查：curl 30s 间隔；`restart: unless-stopped`

### C. Vercel（遗留）【需要确认是否仍在用】

`.vercel/output/` 是 Nitro Build Output v3 旧产物（2026-08-31，早于 Next 迁移）。**若按当前代码部署 Vercel**：serverless 实例无本地盘 → `.data` 不可写（热榜 getRankingStore 返回 null 当不可用）、PGlite 无持久化（每次冷启动丢账号，除非配 DATABASE_URL=Neon + 常驻函数）。当前架构的完整功能只在**常驻进程 + 可写磁盘**形态下成立。

## 8.3 数据备份与恢复

| 对象 | 位置 | 备份方式 | 恢复方式 |
| --- | --- | --- | --- |
| 设置/账号/词表/纸匣目录/历史 | localStorage + user_sync | 设置→备份导出 JSON（不含像素）；或登录应用账号自动同步 | 备份导入（写回 store/IDB 并推服务端）；或登录拉取 |
| 纸匣像素（应用内） | `.data/vault/` | 直接拷贝目录 | 放回原位（SQLite+文件同迁） |
| 纸匣像素（用户文件夹） | 自选目录 | 自行备份（应用只记 relativePath+SHA-256） | 放回原路径，巡检自动校验 |
| 热榜归档 | `.data/rankings/rankings.sqlite` | 拷贝文件 | 放回 |
| 应用账号库 | `.data/kami-db-snapshot.json` | 拷贝文件（或配 DATABASE_URL 走真库） | 启动时自动 restore |
| 封面/列表缓存 | `.data/media` `.data/source` | 无需备份（可再生） | — |

## 8.4 故障恢复速查

| 症状 | 排查 |
| --- | --- |
| 详情页极慢 | 代理是否可达（设置→代理→探测）；undici 池是否被熔断（10min 自动恢复）；看 `.data/dev-server.log` |
| Danbooru 全 403 | Cloudflare 人机验证 → 设置配 Danbooru 账号（Basic 凭据强制 curl） |
| Konachan 拉不到 | 是否处于 Cloudflare 拦杀期（自动切 .net 镜像；日榜镜像数据可能滞后） |
| 登录中转没反应 | 本机是否有 Chrome；`PUPPETEER_EXECUTABLE_PATH` 是否指向有效浏览器 |
| 换浏览器数据全丢 | 未登录应用账号（同步依赖 user_sync）；或强杀进程丢了最近 0.5–30s 写入（快照窗口） |
| 磁盘涨 | `.data/media`（7d 惰性删）与 `.data/source`（30min 惰性删）无主动清理——可整目录删除，安全 |
| LAN 访问异常 | 防火墙放行 8080；确认 host 未改成 127.0.0.1 |

## 8.5 升级与回滚

- 升级：`git pull && pnpm i && pnpm build && pnpm start`（migrate.mjs 幂等；PGlite 运行时迁移同样幂等）。
- 回滚：`git checkout <tag> && pnpm i && pnpm build`。**注意**：0002 之后的迁移目前无 down 脚本——回滚代码不回滚 schema；如引入破坏性迁移，需自备快照（`.data/kami-db-snapshot.json` 即全量账号快照，可直接回拷）。
- Docker：重新 `up --build`；数据在卷内随镜像升级保留。

## 8.6 已知失效的运维工具（勿踩坑）

| 工具 | 状态 | 原因 |
| --- | --- | --- |
| `pnpm preview:restart` / `preview.mjs` | **失效** | 拉起 8080 却等 8081 就绪，且依赖 /proc（Linux-only）——Grok 沙箱时代产物 |
| `pnpm check:auth` | **失效** | 依赖 Vite 插件提供的 `/__app-env` 端点，Next 下不存在，恒返回 indeterminate(exit 2) |
| `node scripts/browser-smoke.mjs` | 部分失效 | 默认输出路径是沙箱路径 `/workspace/screenshots`，本机需显式传参 |
| `/__grok/manifest.webmanifest` | **404 死链** | 动态路由随 Vite/Nitro 消失，app/layout.tsx:30 仍引用（PWA 安装能力实际已失效） |
